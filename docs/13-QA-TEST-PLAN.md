## 1. 테스트 전략 — 자동화에 시간을 쓸 가치가 있는가

### 1.1 결론

> **부분적으로 있다. 단 "순수 함수 + 결정론적 로직"에만, 총 3시간 이내로 제한한다.**
> 그 외 전부는 **수동 스모크 + 치트 콘솔**로 커버한다. E2E/렌더링 테스트는 **전면 배제**한다.

### 1.2 판단 근거 (투자 대비 회수)

| 영역 | 자동화 비용 | 자동화 없이 생기는 손실 | 판정 |
|---|---|---|---|
| **`StatSystem` 계산 순서** (`(기본+Σ가산) × Π곱연산 × 각성`) | **낮음** (순수 함수, 30분) | **치명적.** 정본 §4.2가 "순서가 바뀌면 밸런스가 무너진다"고 명시. 눈으로는 절대 못 잡는다 | ✅ **유닛테스트 필수** |
| **`PactSystem` 카드 생성 규칙** (S1~S6, 중복 방지, MAX 제외, 폴백) | **낮음** (시드 고정 후 10,000회 반복, 60분) | **치명적.** "3장 중 Common 0장" 같은 버그는 100판 돌려도 안 나올 수 있고, 나오면 유저가 좌절한다 | ✅ **유닛테스트 필수** |
| **대가 하한(floor) 클램프** | 낮음 (15분) | 진행 불가 상태(S1 위반) = 출시 차단 버그 | ✅ **유닛테스트 필수** |
| **`requiredExp(level)` 곡선 / 골드 공식** | 매우 낮음 (10분) | 회귀 시 6분에 Lv18~22가 안 나옴 | ✅ **유닛테스트** |
| **세이브 마이그레이션 / 손상 복구** | 낮음 (30분) | 유저 데이터 전소 = 최악의 리뷰 | ✅ **유닛테스트** |
| 각성 6종 효과가 실제 전투에 반영되는가 | 중간 (Phaser 씬 목킹 필요) | 눈으로 5분이면 확인 가능 | ❌ **수동** |
| 렌더링 / 레이아웃 / 좌표 | **매우 높음** (스냅샷 인프라) | 눈으로 즉시 보인다 | ❌ **수동** |
| 입력 (조이스틱, 멀티터치) | **매우 높음** (터치 시뮬레이션) | 손으로 만져야만 알 수 있는 영역 | ❌ **수동** |
| 성능 / fps | 높음 | 프로파일러가 더 정확 | ❌ **계측** |
| 오디오 | 높음 | 귀로 확인 | ❌ **수동** |
| 앱 라이프사이클 / back 버튼 | 매우 높음 (실기기 필요) | 실기기 30초 | ❌ **수동** |

### 1.3 자동화 범위 확정

| 항목 | 값 |
|---|---|
| 러너 | **Vitest** (Vite 7 프로젝트라 설정 파일 1개 + `devDependencies` 1줄로 끝. Jest는 설정 비용이 크다) |
| 총 투자 시간 | **≤ 3시간** (Day 3에 1.5h, Day 5에 1.5h) |
| 테스트 파일 | `src/systems/__tests__/statSystem.test.js`, `pactSystem.test.js`, `saveSystem.test.js`, `progression.test.js` — **4개 이상 만들지 않는다** |
| 목표 케이스 수 | **35 ~ 50개** |
| 커버리지 목표 | **측정하지 않는다.** 커버리지 숫자를 올리는 데 시간을 쓰는 순간 손해다 |
| 실행 시점 | 매일 스모크 전 `npm test` (**5초 이내 완료 필수**) |
| 실패 시 정책 | **빨간 테스트를 안고 다음 날로 넘어가지 않는다.** 고치거나, 테스트가 틀렸으면 지운다 |
| Phaser 의존 | **금지.** 테스트 대상 로직은 `src/systems/`에 Phaser import 없이 순수 함수로 분리한다 (이 분리 자체가 설계 이득) |

> **핵심 논리:** 7일 스코프에서 자동화의 가치는 "버그를 잡는 것"이 아니라 **"밸런스 수치를 겁 없이 바꿀 수 있게 하는 것"** 이다.
> Day 5~7에 반드시 밸런싱을 반복해야 하는데, 이때 StatSystem/PactSystem이 자동 검증되지 않으면 **수치를 만질 때마다 6분 런을 돌려야 한다.** 그게 자동화 3시간보다 훨씬 비싸다.

### 1.4 수동 테스트를 가능하게 하는 필수 도구 (Day 2까지 구축)

> **이 3개가 없으면 나머지 QA 계획이 전부 무의미하다. 최우선 구현.**

| 도구 | 내용 | 접근 |
|---|---|---|
| **치트 콘솔** | `window.BS = { ... }` 전역 객체. 개발 빌드에서만 노출 | `chrome://inspect` 콘솔 |
| **디버그 오버레이** | fps / 적 수 / 파티클 수 / 오브 수 / draw call / 경과시간. `HudScene` 최상단 8px 텍스트 | 5손가락 탭 or `BS.debug()` |
| **텔레메트리 로거** | 런 종료 시 JSON 1줄 콘솔 출력 (§6.3) | 자동 |

**치트 API 목록 (필수)**

```js
window.BS = {
  // 시간/진행
  setTime(sec),            // 인게임 시간 강제 (페이즈 점프)
  setLevel(n),             // 레벨 강제
  addExp(n),
  // 적
  spawn(type, count),      // 특정 적 N체 즉시 스폰
  spawnMax(),              // ★ 적 150체 즉시 채우기 (성능 테스트용)
  killAll(),
  // PACT
  forceCards(rarity),      // 등급 고정 카드 3장 강제
  forceToll(tag, n),       // 특정 태그 n중첩 즉시 부여
  forceAwaken(tag),        // 각성 즉시 발동
  setHumanity(n),          // 인간성 강제 (0 → 완전 흡혈귀화)
  // 플레이어
  god(bool), setHp(n), giveWeapon(id, lv),
  // 보스
  spawnBoss(), bossPhase(n),
  // 계측
  fps(), stats(), dumpRun(),
  lowSpec(bool), shake(bool),
};
```

## 2. 일일 스모크 테스트 체크리스트 (5분)

> **매일 개발 종료 시 반드시 실행.** 실기기 1대에서. 실패 항목은 다음 날 아침 최우선.
> 순서를 지킬 것 — 앞 단계가 깨지면 뒤는 볼 필요가 없다.

### 2.1 빌드 & 기동 (60초)

- [ ] `npm run lint` 통과 (에러 0)
- [ ] `npm test` 통과 (5초 이내, 실패 0)
- [ ] `npm run build` 성공, **번들 크기 확인** (기대: JS < 2.5MB, 총 assets < 60MB)
- [ ] `npx cap sync android` → Android Studio 실행 or `npm run cap:run:android` 성공
- [ ] 앱 아이콘 탭 → **스플래시 → 타이틀까지 5초 이내** (기대: 콘솔 에러 0)

### 2.2 화면 & 방향 (40초)

- [ ] 앱이 **가로로 시작**한다 (기기를 세로로 들고 실행해도 가로) — 기대: landscape 고정
- [ ] 기기를 180° 뒤집어도 가로 유지, 레이아웃 붕괴 없음
- [ ] 좌우 레터박스가 **검정(`#0b0710`)** 이고 게임 화면이 정중앙
- [ ] 노치/펀치홀이 게임 화면을 가리지 않는다
- [ ] 하단 제스처 바가 대시 버튼과 겹치지 않는다

### 2.3 코어 루프 90초 (150초)

- [ ] 타이틀 → **런 시작** 탭 → 1초 이내 게임 진입
- [ ] 좌측 아무 곳 터치 → **그 자리에 조이스틱 생성**, 캐릭터 즉시 이동
- [ ] 손가락을 화면 밖으로 빼기 → 캐릭터가 **멈추지 않고 계속 이동**
- [ ] 우측 대시 버튼 탭 → 순간이동 + 쿨 링 3초 회전
- [ ] 적이 다가오면 **무기가 자동 발동** (플레이어 입력 없이)
- [ ] 적 처치 → 흰 플래시 + 데미지 숫자 + EXP 오브 드롭
- [ ] EXP 오브가 자석 반경에서 빨려 들어옴
- [ ] **15초 이내 첫 레벨업** → PACT 카드 3장 등장
- [ ] Lv2 카드에 **대가가 없다** (안전장치 S4)
- [ ] 카드 1탭 → 선택 표시, 2탭 → 확정 후 게임 재개
- [ ] **90초 시점 페이즈 전환 토스트** 표시 (`— 01:00 축시 —`)
- [ ] 이 90초 동안 **fps ≥ 55** (디버그 오버레이 확인)

### 2.4 PACT & 각성 (60초, 치트 사용)

- [ ] `BS.setLevel(10)` → 카드 3장 중 **최소 1장이 Common** (S3)
- [ ] `BS.forceToll('SLOW', 2)` 후 레벨업 → 3중첩 카드에 **금빛 맥동 + "이 계약으로 각성한다"**
- [ ] 해당 카드 선택 → **각성 연출 2초** 재생 (플래시/타이포/충격파/넉백)
- [ ] 각성 후 HP가 30% 회복됨 (S6)
- [ ] HUD 각성 카운터 `✦1` 표시
- [ ] 리롤 버튼 탭 → 카드 3장 전체 재생성, 잔여 횟수 감소
- [ ] 거절 버튼 탭 → HP 25% 회복 + 인간성 **감소 없음**

### 2.5 종료 & 저장 (50초)

- [ ] 일시정지 버튼 → 게임 정지, 우측에 **현재 계약 패널** 표시
- [ ] 계속 → 3-2-1 카운트다운 후 재개
- [ ] 앱을 홈 버튼으로 백그라운드 → 복귀 시 **일시정지 상태**
- [ ] 안드로이드 **back 버튼** → 일시정지 열림 (게임 종료 안 됨)
- [ ] 포기 → 결과 화면, 골드 표시
- [ ] 결과 → 타이틀 → **골드가 반영되어 있음**
- [ ] 앱 완전 종료 후 재실행 → **골드 유지** (localStorage)
- [ ] 콘솔에 `[BS-TELEMETRY] {...}` 1줄 출력됨

## 3. 기능별 테스트 케이스

> 우선순위: **P0** = 실패 시 출시 차단 / **P1** = 실패 시 재미 저해, 반드시 수정 / **P2** = 여유 있으면 수정
> `AUTO` 표시 = Vitest 자동화 대상

### 3.1 입력 (IN)

| ID | 대상 | 사전조건 | 절차 | 기대결과 | 우선 |
|---|---|---|---|---|---|
| IN-01 | 플로팅 조이스틱 생성 | 게임 진행 중 | 좌측 절반 임의 지점 터치 | 터치 지점이 원점인 조이스틱 즉시 생성(0프레임 지연). 베이스 링 r=40 알파 0.30, 노브 r=14 | P0 |
| IN-02 | 8방향 이동 | 게임 중 | 조이스틱을 시계 방향으로 천천히 1회전 | 캐릭터가 끊김 없이 8방향 이상 연속 회전 이동. 스냅 없음. 스프라이트 4방향 애니메이션 전환 | P0 |
| IN-03 | 데드존 | 게임 중 | 원점에서 반경 7px 이내로만 미세 이동 | 캐릭터 **완전 정지**(속도 0). 반경 9px에서 아주 느리게 이동 시작 | P0 |
| IN-04 | 최대 속도 정규화 | 게임 중 | 반경 48px 지점과 반경 120px 지점(밖) 비교 | 두 지점의 이동 속도가 **동일**(70px/s). 48px 초과분은 방향만 반영 | P1 |
| IN-05 | 원점 드리프트 | 게임 중 | 손가락을 원점에서 200px 드래그 | 원점이 손가락을 따라 이동해 항상 48px 이내 유지. 팔이 화면 끝까지 안 가도 됨 | P2 |
| IN-06 | **화면 밖 드래그** | 게임 중 | 조이스틱을 잡고 화면 왼쪽 가장자리 밖으로 손가락을 뺌 | 캐릭터가 **멈추지 않고 마지막 방향으로 계속 이동**. 손가락을 다시 화면 안에 넣으면 정상 추종 | **P0** |
| IN-07 | pointer 유실 워치독 | 게임 중 | 화면 밖으로 뺀 뒤 다른 앱 알림을 내려 pointer 이벤트 유실 유도 | 1.0초 내 입력 0으로 리셋. **무한 이동 안 함** | P0 |
| IN-08 | 멀티터치 — 조이스틱+대시 | 게임 중 | 왼손으로 조이스틱 유지한 채 오른손 대시 탭 | 둘 다 정상 동작. 조이스틱 입력 끊김 없음. 대시 방향 = 현재 이동 방향 | **P0** |
| IN-09 | 멀티터치 — 좌측 2개 | 게임 중 | 좌측에 손가락 A 유지 후 좌측에 B 추가 터치 | B 무시. A만 조이스틱 소유. A를 떼면 B가 이어받지 **않음** | P1 |
| IN-10 | 3손가락 이상 | 게임 중 | 4손가락 동시 터치 | 크래시 없음. 3번째 이상 전부 무시 | P1 |
| IN-11 | 대시 쿨다운 | 게임 중 | 대시 버튼 연타 (10회/2초) | 최초 1회만 발동. 쿨 3.0초 후 재발동. 쿨 링이 정확히 3초에 완주. 큐잉 없음 | P0 |
| IN-12 | 대시 무적 | 게임 중, 적 밀집 | 적 무리에 대시로 돌입 | 대시 시작~0.25초 동안 피격 0. 0.26초부터 피격됨 | P0 |

| 40 ≤ 1% Low < 45 | ⚠️ 조건부. **저사양 모드 자동 제안 임계를 40fps로 켜고 출시 가능**. 단 조치 1~3 시도 |
| 1% Low < 40 | ❌ **출시 차단.** 조치 1~6을 순서대로 적용 |

| # | 조치 | 예상 효과 | 비용 |
|---|---|---|---|
| 1 | **데미지 숫자 상한 24 → 12**, 150ms 합산 강화 | +3~6fps | 5분 |
| 2 | **파티클 상한 120 → 60**, 처치 파티클 4→2 | +3~5fps | 5분 |
| 3 | **EXP 오브 합체 임계 200 → 120** | +2~4fps | 10분 |
| 4 | **적 상한 150 → 120** (정본 수치 변경 — 마지막 수단) | +6~10fps | 밸런스 재확인 필요 |
| 5 | 적 AI 업데이트를 **프레임 분할**(150체를 3그룹으로 나눠 1/3씩 갱신) | +5~8fps | 30분, 이동이 미세하게 덜컹 |

## 5. 디바이스 테스트 매트릭스

> **이 절은 Android + iOS 동시 배포를 전제로 재설계되었다.**
> 핵심 제약은 하나다 — **Mac이 없다.** 이것이 iOS 검증 설계 전체를 결정한다:
>
> - **iOS 시뮬레이터를 쓸 수 없다.** 시뮬레이터는 macOS 전용이고, Capacitor 공식 입장도 "iOS 앱을 빌드하려면 macOS가 필요하다"이다.
> - **`.ipa`를 시뮬레이터에서 실행할 수도 없다.** 아키텍처가 아니라 **플랫폼이 다르기 때문**이다(`arm64-apple-ios` vs `-ios-simulator`). `npx cap build ios` 의 export method에 시뮬레이터 산출물이 아예 없다.
> - 따라서 **iOS는 "에뮬레이터로 싸게 반복"이 원천적으로 불가능**하다. 모든 iOS 확인은 실기기(직접 또는 원격)를 거친다.
>
> **결론: iOS 검증은 §5.1 매트릭스로 해결되지 않는다. → §5.4에서 별도 설계한다.**

> 이 불일치를 숨기지 않는다 — 구형 iOS에서 깨질 가능성은 남아 있고, 그것을 **알면서 감수하는 것**이 이번 주의 결정이다(→ `16-RISKS` R26).

| 미검증 항목 | 영향 | 판단 |
|---|---|---|
| **실제 손맛 / 입력 지연** | 중 | 같은 `dist/`가 Android 실기기에서 검증되었고, 조작 처리는 전부 웹 계층이다. **플랫폼 고유 위험이 낮다** |
| **실제 성능 / 프레임** | 중 | 위와 동일 근거. 다만 WKWebView와 Android WebView는 엔진이 다르므로 **동일 보장은 아니다** |
| **무음 스위치 실동작** | 하 | 기본 동작 유지 방침이므로 실패해도 "소리가 안 남" |
| **iOS 14~16 구세대** | 중 | 팜 기기 라인업에 있으면 1회, 없으면 미검증 (→ §5.3) |

> **→ 갈래 B로 갈 경우 `16-RISKS` R26("iOS 실기기 미검증 출고")을 반드시 활성 상태로 유지한다.** 이건 완화하는 리스크가 아니라 **받아들이는 리스크**다.

#### 5.4.4 시뮬레이터를 포기한다 — 결정과 근거

| # | 근거 |
|---|---|
| 1 | **애초에 불가능하다.** 시뮬레이터는 macOS 전용이고 Mac이 없다 |
| 2 | 설령 클라우드 Mac을 빌려도, **`.ipa`는 시뮬레이터에서 안 돈다.** 시뮬레이터용 산출물을 CI에서 **하나 더** 만들어야 한다 = 파이프라인이 2개가 된다 |
| 3 | 정작 중요한 두 가지를 **시뮬레이터로는 검증할 수 없다** — ① 실제 **저장소 회수 동작**(SV-12~14) ② 실제 **터치감·프레임** |
| 4 | 즉 비용은 실재하고 이득은 레이아웃 확인뿐인데, **레이아웃은 D-2 Chrome 커스텀 디바이스로 이미 본다** |

> **클라우드 Mac은 "빌드가 아니라 진단이 막혔을 때"의 최후 수단으로만 둔다.**
> 참고 단가: Scaleway M1-M €0.11/hr이지만 **24시간 최소 과금 → 세션당 약 €2.64** / AWS EC2 Mac $0.650/hr·24시간 최소(약 $15.60) / MacinCloud $1/hr·25시간 선불 / MacStadium $109/월.
> **24시간 최소 과금이 공통 함정**이다. "1시간만 빌린다"가 성립하지 않는다.

#### 5.4.5 최종 판정표 — 어느 항목을 어디서 판정하는가

| 판정 대상 | Android | iOS (갈래 A) | iOS (갈래 B) |
|---|---|---|---|
| 게임 로직·밸런스 | D-1 실기기 | **Android 결과 승계** | **Android 결과 승계** |
| 레이아웃·화면비 | D-2 + D-1 | D-2 + TestFlight 실기 | D-2 + 디바이스 팜 |
| 성능 / fps | **D-1 실기기 (유일 판정처)** | TestFlight 실기 참고 | **판정 불가 — Android 승계** |
| 손맛 / 입력 지연 | **D-1 실기기** | **TestFlight 실기** | **판정 불가 — 미검증 기록** |
| 저장 유지 | D-1 | **TestFlight 실기 (SV-12~14)** | 디바이스 팜 |
| 무음 스위치 | 해당 없음 | **실기 (AU-11)** | **불가 — 미검증 기록** |
| 홈 인디케이터·앱 전환 | D-1(제스처 바) | 실기 (SC-15/16) | 디바이스 팜 |
| 크래시·부팅 | D-1 | TestFlight | 디바이스 팜 |

> **가장 중요한 한 줄:** iOS에서 **새로 판정해야 하는 것은 플랫폼 고유 실패 모드 9건뿐**이고(§3 iOS 전용 케이스), 나머지는 **Android 결과를 승계**한다.
> 같은 `dist/`를 쓰기 때문에 이 승계가 성립한다. **이 전제가 깨지는 순간**(iOS 전용 코드 분기가 생기는 순간) **iOS QA 비용이 2배가 된다** — 그래서 이번 주에 iOS 전용 코드 분기를 만들지 않는다.

## 6. 밸런스 플레이테스트 프로토콜

### 6.1 문제 정의 — "개발자 편향"

1인 개발자는 7일 동안 **자기 게임을 수백 번 플레이한다.** 그 결과:
- 조작이 손에 붙어 있어 **난이도를 과소평가**한다 → 실제 유저에겐 지나치게 어렵다.
- 시스템을 알고 있어 **PACT 선택이 3초가 아니라 0.5초**다 → UI 정보 위계가 나쁜 걸 못 느낀다.
- 매번 최적 빌드를 고르므로 **약한 빌드의 존재**를 모른다.
- "여기서 죽는 건 내가 실수해서"라고 해석한다 → **밸런스 문제를 실력 문제로 오귀인**한다.

### 6.2 편향을 줄이는 실전 방법 (7일 안에 실제로 할 수 있는 것만)

| # | 방법 | 실행 | 소요 |
|---|---|---|---|
| **B-1** | **지표를 믿고 감을 믿지 않는다** | 모든 런의 §6.3 지표를 자동 로깅. 판단은 **숫자로만** | 구현 30분 |
| **B-2** | **비지배 손으로 플레이** (한손/반대손) | 하루 1런은 왼손만으로. 조작 숙련도를 인위적으로 낮춰 "초보 시점" 복원 | 6분/일 |
| **B-3** | **랜덤 선택 런** (Monkey Run) | 하루 1런은 카드를 **무작위로** 선택(`BS` 치트로 자동 선택). 최적 플레이가 아닌 평균 플레이의 난이도 확인 | 6분/일 |
| **B-4** | **외부인 테스트 (필수)** | Day 5~6에 **1~2명**, 각 **5분 세션 2회**. 게임 설명 **절대 금지** | 30분 |
| **B-5** | **콜드 오픈 규칙** | 매일 첫 런은 워밍업 없이 바로. 그날의 "감"을 기록 (1~5점) | 0분 |
| **B-6** | **첫 런 데이터만 따로 본다** | 세이브 초기화 후 첫 런 지표를 별도 수집. 성소 강화 0 상태가 진짜 난이도 | 6분 |
| **B-7** | 24시간 룰 | 밸런스 수치 변경은 **하루에 1회만**, 그리고 5런 이상 데이터를 본 뒤에만 | — |

### 6.4 외부인 테스트 프로토콜 (Day 5~6, 1~2명)

**준비 (5분)**
- 실기기에 최신 빌드 설치, 세이브 **초기화**(성소 강화 0)
- 텔레메트리 ON, 화면 녹화 ON (Android 기본 화면 녹화)
- **한 마디도 설명하지 않는다.** "이거 한번 해보세요"만.

**세션 1 (5분) — 순수 첫 경험**

| 관찰 항목 | 기록 방법 | 판정 기준 |
|---|---|---|
| **첫 터치까지 걸린 시간** | 스톱워치 | ≤ 2초. 초과 = 조이스틱 힌트 실패 |
| **조이스틱을 찾았나** | 좌측을 터치했는가 | 헤매면 고스트 힌트 강화 필요 |
| **대시 버튼을 눌렀나** | 첫 5분 내 사용 여부 | 미사용 = 시각 알파 0.45가 부족 |
| **공격이 자동임을 인지했나** | 화면을 탭하며 공격 시도하는가 | 탭 시도 = 온보딩 ② 실패 |
| **첫 카드에서 무엇을 봤나** | 시선/손가락 이동 관찰 | 축복 이름 → 대가 순이면 정상 |
| **첫 카드 판단 시간** | 텔레메트리 | 3~10초. 10초 초과 = 정보 과다 |
| **"대가"를 언제 눈치챘나** | 표정/발화 | Lv4에서 반응 없으면 지연 페이드 연출 실패 |
| **각성에 반응했나** | 발화 ("오" "뭐야" 등) | **무반응 = 연출 실패, 최우선 수정** |
| 어디서 죽었나 | 텔레메트리 | 1분 미만 사망 = 초반 난이도 과함 |
| **한 판 더 하려 하나** | 자발적 재시작 여부 | **가장 중요한 단일 지표** |

**세션 2 (5분) — 학습 후**
- 여전히 설명 없음. 2번째 런.
- 관찰: 리롤/스킵을 쓰는가 / 태그를 의도적으로 모으는가 / 생존 시간이 늘었는가

**세션 후 질문 (3개만, 유도 금지)**
1. "지금 무슨 게임이었어요?" → **PACT 구조를 설명하면 온보딩 성공**
2. "카드 고를 때 뭘 보고 골랐어요?" → 정보 위계 검증
3. "언제가 제일 재밌었어요 / 답답했어요?" → 병목 발견

**금지 사항**
- ❌ 플레이 중 조언, 힌트, "그거 아니고 이거요"
- ❌ "재밌어요?" 같은 예/아니오 질문 (사회적 압력으로 무조건 "네")
- ❌ 결과를 방어하거나 설명하려는 시도
- ✅ 침묵하고 관찰하고 메모만 한다

| # | 항목 | 통과 조건 | 재현 방법 |
|---|---|---|---|
| E-1 | 조우가 게임을 멈추지 않는다 | 조우 중 `scene.isPaused()` 가 항상 false | `BS.enc(k)` 후 `BS.encState().paused` 를 연속 표본. **레벨업 PACT 와 섞으면 측정이 안 된다** — `checkLevelUp` 을 임시로 막고 잰다 |
| E-2 | 조작이 늘지 않았다 | 조이스틱·대시 외 입력 핸들러 0 | 조우 7종을 전부 띄운 전후로 각 씬의 `input._events` 를 비교. `.enc-layer` 하위에 `pointer-events !== none` 인 요소 0 |
| E-3 | 체력이 0 이하로 지불되지 않는다 | 잔여 체력이 가격 **이하**면 구매 차단 | `hp = maxHp * 0.25` 로 두고 25% 좌판을 밟는다. `canPay(0.25) === false` (미만이 아니라 이하다 — 같으면 0 이 되고 그건 죽는 것이다) |
| E-4 | 필드보스가 런을 끝내지 않는다 | 처치 후 `spawner.suppressed === false`, `RUN_ENDED` 미발생, 잡몹 정화 없음 | `BS.enc('fieldboss')` → 강제 처치 → `dead/paused/bossSystem.defeated` 전부 false, 이후에도 잡몹 수가 는다 |
| E-5 | 필드보스를 무시할 수 있다 | 리시 반경(140px) 밖에서 추적 안 함, 60초 후 소멸, 피해 0 | 400px 밖에 서서 12초 관측 — 스폰 지점 이탈이 리시 반경 안에 머문다. 120px 로 다가가면 추적이 시작된다 |
| E-6 | 디렉터가 같은 조우를 연속 배치하지 않는다 | 100런 시뮬레이션에서 연속 0회 | `BS.encSim(100)` 의 `repeats === 0`. 마녀가 못 나오는 경우도 봐야 한다 — `BS.encSim(100, 0)` (제시 가능 룬 0개) |
| E-7 | 성능 | 조우 활성 + 적 150체에서 **1% Low >= 40fps** (평균이 아니다) | `BS.wave(11); BS.spawn(150); BS.enc('merchant')` 후 좌판 옆에서 10초 이상 관측, `sc.quality.low1` |
| E-8 | 런 중 `new` 금지 | 조우 오브젝트 전부 풀링 | 조우를 21회 띄웠다 걷은 뒤 `sc.children.list.length` 가 그대로다 |

**E-1 의 함정**: 이 런에서 정지가 일어나는 유일한 원인은 PACT 레벨업이다. 적 150체를 스폰하면
레벨업이 연달아 터져 표본의 90%가 정지로 잡힌다. **조우가 정지를 만드는가**를 재는 시험이므로
레벨업을 잠시 막고 재야 한다. 소스 수준 보증도 함께 본다 — 주석을 걷어낸 `EncounterSystem.js` 에
`scene.pause(` / `scene.input` / `addEventListener` / `setInteractive` 가 각각 0건이어야 한다.

**E-5 의 함정**: 필드보스 10종은 AI 가 섞여 있다(`chase` / `charge` / `shockwave`).
`charge` 형은 돌진 쿨다운 때문에 3초 안에 거리를 못 좁힌다 — 리시 경계 시험은 `chase`/`zigzag` 형이
뽑힐 때까지 다시 뽑아서 재야 오탐이 안 난다.

### 12.3 ★ `pact.awakened` 수정의 부작용

`AwakeningSystem.trigger` 의 `this.pact?.awakened?.add(tag)` 한 줄이 살아난 것을 **라이브로 먼저 확인**했다 —
`trigger('SLOW')`·`trigger('GREED')` 후 `[...pact.awakened] = ["SLOW","GREED"]`, `atCap=true`,
세 번째 `trigger('FRAIL')` 은 `false` + 인간성 **100→80**(상한 초과 −20).

그다음 `StatSystem`·`PactSystem` 인스턴스를 새로 만들어 Lv2~30 레벨업을 **800런씩** 시뮬레이션하고,
`awakened.add` 를 하지 않는 **옛 동작**과 나란히 놓았다.

| 지표 (런당) | 옛 동작 | 현재 | 판정 |
|---|---|---|---|
| 각성한 태그가 카드에 **다시 제시**된 횟수 | 17.1 / 17.8 | **0 / 0** | 수정 의도 달성 |
| Lv4+ 카드 중 **대가 없는 카드** 비율 | 0% | **31.5%**(무작위) / **36.1%**(욕심) | ⚠ **새 부작용** |
| **제단**이 대가 없이 지나가는 비율 | 0% | **42.9% / 49.1%** | ⚠ **새 부작용** |
| **마녀**가 대가 없이 룬만 주는 횟수 | 0 | 0.16 / 0.50 | ⚠ **새 부작용** |
| 상한 초과 **−20** 발생 횟수 | 3.40 / 3.65 | **3.00 / 2.17** | 과해지지 않았다 (오히려 감소) |
| 인간성 0 「완전 흡혈귀화」 도달률 | 100% | 97.8% / 94.1% | ⚠ 거의 안 줄었다 |
| 평균 최종 인간성 | 0.0 | 0.2 / 1.1 | |

**레벨별 「대가 없는 카드」 비율** (무작위 선택, 600런)

```
Lv4~12  0%   Lv13  1%   Lv14  5%   Lv15 10%   Lv16 21%   Lv17 31%   Lv18 42%
Lv19   49%   Lv20 54%   Lv22 60%   Lv25 64%   Lv28~30 66%
```

각성 상한(2) 도달 레벨 **중앙값 12**(최소 7 / 최대 17), **100% 의 런이 상한에 도달**한다.

**원인** — `pickToll` 은 상한 도달 후 `willOverflow`(`cur + addStacks >= 3`) 인 태그를 **후보에서 통째로 뺀다**
(`allowOverflow` 는 마지막 장에만 true). 각성한 2태그는 영구 제외이므로 남는 것은 4태그뿐이고,
그 4태그가 2중첩에 닿는 순간 **후보가 0이 되어 대가 없이 지나간다**.

**라이브 재현 절차** (제단이 순수 이득으로 돌아가는 경로)

1. `?debug=1` 로 런 시작
2. 콘솔에서 각성 2개를 채운다
   ```js
   const sc = __PHASER_GAME__.scene.getScene('GameScene');
   sc.pact.tagCounts.SLOW = 2;  sc.combatSystem.awakening.trigger('SLOW');
   sc.pact.tagCounts.GREED = 2; sc.combatSystem.awakening.trigger('GREED');
   ```
3. 남은 4태그를 2중첩으로 — `BS.toll('FRAIL',2) BS.toll('MYOPIA',2) BS.toll('BLIND',2) BS.toll('HUNGER',2)`
4. `for (let i=0;i<8;i++) console.log(sc.encounters.rollToll('rare'))` → **8회 전부 `null`**
5. `BS.enc('altar')` → 제단 위에서 3초

**결과**: `pact.humanity` **100 그대로**, `tagCounts` **그대로**, `Object.keys(pact.owned).length` **0→1**
— **epic 축복 1개를 대가 0 · 인간성 0 으로 받는다.**
같은 상태에서 `BS.enc('witch')` 로 룬을 사면 룬만 각인되고 `tagCounts` 는 불변이다(hp 만 −15%).

**의미**: 2026-08-11 에 「제단이 PACT epic 카드의 순수 상위 호환이라 인간성을 받게 했다」고 고친 것이
런 후반에 **절반쯤 되돌아간다**. 그리고 「강해지는 것은 언제나 대가를 동반한다」는 PACT 의 문법이
Lv20 이후 카드의 **2/3 에서 성립하지 않는다**.
`PactSystem.pickToll` 주석이 목표로 잡은 「P2 특수 상태(완전 흡혈귀화)가 기본값이 되면 안 된다」도
아직 달성되지 않았다 — 94~98% 다. 남은 −20 의 출처는 **마지막 장(`i===2`, `allowOverflow=true`)** 이다.

★ 이 절은 **판단이 아니라 관측**이다. 수정은 하지 않았다.
