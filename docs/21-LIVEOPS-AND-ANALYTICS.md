## 0. 이 문서가 존재하는 이유

7일 스프린트에서 방향을 정한 것은 **내 감각**이었다. 판단 근거가 "자가 플레이 10판"이었고,
그 정도 표본에서는 감각이 실제로 가장 좋은 도구였다.

6개월 · 1000만 사용자 · 수익화로 목표가 바뀌면서 **그 도구가 더 이상 통하지 않는다.**

| | 7일 스프린트 | 6개월 라이브옵스 |
|---|---|---|
| 판단 주체 | 나 | **데이터** |
| 표본 | 자가 플레이 10판 | 수천 명 × 수만 런 |
| 틀렸을 때 비용 | 하루 | **한 마일스톤(4~6주)** |
| "재미없다"의 의미 | 내가 안 재밌다 | **D7에 안 돌아온다** |

> **핵심 전환:** 소프트런치 전에 만들어야 할 것은 콘텐츠가 아니라 **측정 가능성**이다.
> 콘텐츠는 소프트런치 후에도 만들 수 있지만, **측정되지 않은 4주는 영원히 복구되지 않는다.**
> 계측이 빠진 채 소프트런치를 시작하면 4주를 쓰고 나서 "잘 모르겠다"가 남는다. 그게 최악의 결과다.

## 0.1 ⚠️ 벤치마크를 읽기 전에 — 이 문서의 숫자 규칙

**이 문서의 모든 외부 수치는 출처와 등급을 붙인다. 출처가 없으면 없다고 적는다.**

| 등급 | 뜻 | 이 문서에서의 취급 |
|---|---|---|
| **A** | SDK·플랫폼 실측 1차 데이터 (GameAnalytics / AppsFlyer / Adjust / Liftoff / Appodeal / AppTweak) | **판정 기준선으로 채택** |
| **B** | 1차 보고서를 인용한 업계지 (MobileGamer.biz / Naavik / Lancaric / Mistplay) | 방향성 참고. 기준선으로 쓰지 않음 |
| **C** | 원출처 미표기 SEO 블로그 | **채택 금지.** 이 문서에 등장하지 않음 |
| **없음** | 조사했으나 1차 출처를 찾지 못함 | **"출처 없음 — 소프트런치에서 직접 측정"으로 명시** |

**반드시 알아야 할 함정 3가지**

1. **모집단이 다른 표를 섞으면 안 된다.** GameAnalytics(전수 포함, D1 중앙값 약 20%)와
   AppsFlyer/Adjust(UA를 집행하는 규모 있는 게임 위주, D1 27~30%)는 **다른 모집단**이다.
   우리는 소프트런치에서 유료 UA를 돌리므로 **후자를 기준선으로 쓴다.**
2. **장르별 리텐션 표는 2022년 데이터다.** 흔히 인용되는 장르별 D1/D7/D30 표는
   AppsFlyer Q3 2022 단일 데이터의 재인용이며, **2025~2026 신규 장르별 표는 공개된 것이 없다.**
3. **서바이버즈 장르 전용 벤치마크는 존재하지 않는다.** Survivor.io / Archero / 20 Minutes Till Dawn의
   리텐션·ARPDAU는 어디에도 공개되지 않았다. → **Action과 Shooting의 중간을 대리 지표로 쓴다.**

## 1. 무엇을 측정해야 방향이 정해지는가

**측정 항목을 늘리는 것은 쉽고, 그래서 위험하다.** 대시보드가 40개면 아무것도 안 본다.
아래는 **"이 숫자가 나쁘면 다음 마일스톤의 계획이 바뀐다"** 는 기준만 통과한 항목이다.

### 1.1 5개 질문 — 이것 말고는 묻지 않는다

| # | 질문 | 대표 지표 | 나쁠 때 고치는 곳 |
|---|---|---|---|
| **Q1** | **설치한 사람이 게임에 도달하는가** | 첫 런 시작률, 첫 런 완주율 | 온보딩·로딩·크래시 |
| **Q2** | **한 판이 재밌는가** | 런 길이 분포, **이탈 페이즈**, 클리어율 | 밸런스·난이도 곡선 |
| **Q3** | **내일 돌아오는가** | D1 / D7 / D30 | 메타 진행·해금 리듬 |
| **Q4** | **돈이 되는가** | ARPDAU, 광고 시청률, 결제 전환율 | 광고 지점·상품 구성 |
| **Q5** | **얼마에 데려올 수 있는가** | CPI, 오가닉 비중 | 크리에이티브·ASO·GEO |

> **Q1→Q5 순서를 반드시 지킨다.** Q1이 깨진 상태에서 Q4를 고치는 것은 **밑 빠진 독에 상품을 얹는 일**이다.
> 소프트런치 4주 중 **1주차는 Q1·Q2만 본다.** 리텐션은 정의상 1주가 지나야 읽히므로 그전에 보는 것은 노이즈다.

### 1.2 ★ 이탈 지점 — 이 게임에서 가장 중요한 단일 지표

**리텐션은 결과지 원인이 아니다.** "D7이 5%다"는 무엇을 고칠지 알려주지 않는다.
**"3:00 페이즈에서 60%가 죽고 그중 70%가 재시작하지 않는다"** 는 알려준다.

우리 게임은 런이 **6분 · 90초마다 페이즈 전환(정본 GDD §11)** 이라는 고정 구조를 가진다.
이 구조가 **이탈 분석에 이례적으로 유리하다** — 이탈 지점이 연속값이 아니라 **7칸 버킷**으로 떨어진다.

```
런 종료 시각 버킷 (초)
 [0:00–0:30)  ← 조작을 이해 못 함 / 크래시 / 오해
 [0:30–1:30)  ← 페이즈 1
 [1:30–3:00)  ← 페이즈 2 (첫 엘리트)
 [3:00–4:30)  ← 페이즈 3 (원거리 적 진입)
 [4:30–6:00)  ← 페이즈 4 (최대 밀도)
 [6:00–  ]    ← 보스전
 클리어
```

| 패턴 | 읽는 법 | 조치 |
|---|---|---|
| 0:00–0:30 이탈이 **10% 초과** | 게임에 도달하지 못했다. 조작·로딩·크래시 문제 | **최우선.** 밸런스보다 앞선다 |
| 특정 버킷에 사망이 몰림 | 난이도 절벽 | 그 페이즈의 `hpMult`·스폰 간격 조정 |
| 보스전 진입률은 높은데 클리어율 < 20% | 보스만 어렵다 | 보스 HP(현재 11,000) 조정 |
| 클리어율 > 60% | 너무 쉽다. 장기 리텐션이 먼저 죽는다 | 난이도 티어 추가 |
| **런 종료 후 재시작률** < 40% | 한 판이 "또 하고 싶지" 않다 | ★ **가장 위험한 신호.** 결과 화면·메타 보상 |

> **재시작률(같은 세션 내 연속 런 수)은 D1보다 먼저 읽힌다.** 설치 당일에 나오므로
> **소프트런치 1주차에 유일하게 신뢰할 수 있는 재미 지표**다. D1을 기다리지 말고 이것부터 본다.
> 참고: 설치 당일 평균 세션 수 **1.65회** (Adjust *Gaming App Insights Report 2026*, A등급).
> 즉 **첫 세션 안에서 결판이 난다** — 두 번째 세션은 대부분 오지 않는다.

## 2. 판정 기준선 — 미달 시 무엇을 고치는가

> **기준선은 "합격점"이 아니라 "계획을 바꾸는 선"이다.**
> 통과하면 다음 마일스톤을 예정대로 간다. 미달하면 **다음 마일스톤의 내용이 바뀐다.**
> 판정은 소프트런치 **2주차 종료 시 1차 · 4주차 종료 시 최종**, 총 2회만 한다.
> 매일 보면 노이즈에 반응하게 되고, 노이즈에 반응하는 것이 소프트런치 실패의 가장 흔한 형태다.

> 게임이 나쁘다는 뜻이 아니다. **크리에이티브가 게임 내용과 다를 때** 전형적으로 이 모양이 나온다
> → `25-GROWTH-AND-UA.md` §3. 이 경우 고칠 곳은 게임이 아니라 **광고 소재**다.

### 2.2 세션 · 런

**참조 벤치마크 (A등급)**

| 출처 | 수치 |
|---|---|
| GameAnalytics *2026* | 일일 플레이타임 중앙값 ~12분 / 상위 25% 22~24분 / 상위 10% 40~42분 |

**우리 판정선** — 런이 6분 고정이므로 세션 길이는 **"세션당 런 수"** 로 환산해서 본다.

| 지표 | 🟢 통과 | 🔴 실패 | 실패 시 조치 |
|---|---|---|---|
| **세션당 런 수** | **≥ 2.0** | < 1.5 | 결과 화면 → 재시작 마찰. **3초 재시작 규칙(정본 GDD §12) 실측 검증** |
| 일일 플레이타임 | ≥ 15분 | < 8분 | 위와 동일 |
| **0:00–0:30 이탈률** | **≤ 7%** | > 12% | 온보딩·로딩·크래시. **최우선** |
| **런 클리어율** | **25~45%** | <10% 또는 >60% | 보스 HP·페이즈 배율 조정 (`05-COMBAT-AND-BALANCE.md`) |
| **각성 발동률** (런당 1회 이상) | ≥ 70% | < 50% | PACT 밸런스. **이게 무너지면 게임의 정체성이 전달되지 않은 것** |

> ★ **각성 발동률은 벤치마크가 없는, 그러나 우리에게 가장 중요한 지표다.**
> 정본 검산(`README.md` §검산)은 "각성 0회가 수학적으로 불가능"하다고 결론냈다.
> **실측이 그와 다르면 검산이 아니라 구현이 틀린 것이다.** 이 지표는 밸런스가 아니라 **버그 탐지**로 쓴다.

| 결제 전환율 (D30) | ≥ 2% | < 0.8% | 상품 구성. **가격이 아니라 "무엇을 파는가"부터 본다** |
| 광고 시청자의 D7 | **비시청자 이상** | 비시청자 미만 | 🔴 **즉시 광고 축소.** 광고가 리텐션을 먹고 있다 |

> ★ **마지막 줄이 이 표에서 가장 중요하다.** 광고 매출은 항상 즉시 보이고, 광고가 깎아먹는 리텐션은 항상 늦게 보인다.
> 그래서 **"시청 코호트 vs 비시청 코호트의 D7"을 상시 감시 지표로 고정**한다.
> 이 비교가 역전되면 ARPDAU가 아무리 좋아도 **광고를 줄인다.** 예외 없다.

## 3. 이벤트 스키마

> **구현 계약은 이미 `FE/src/analytics/index.js`에 있다.** 이 절은 그 계약의 `ANALYTICS_EVENTS` 13종에
> **어떤 속성이 붙어야 §1의 질문에 답할 수 있는가**를 정의한다. **이벤트를 늘리지 않는다** —
> 늘어난 이벤트는 구현 비용·전송 비용·분석 피로를 전부 늘리는데, 답하는 질문은 늘지 않는 경우가 대부분이다.

### 3.1 공통 속성 (모든 이벤트에 자동 부착)

| 키 | 타입 | 예 | 비고 |
|---|---|---|---|
| `uid` | string | `"a3f1…"` | **기기 로컬 생성 익명 UUID v4.** 이것이 유일한 식별자다 (§5) |
| `ts` | int | `1786…` | epoch ms |
| `session_id` | string | UUID | 앱 포그라운드 진입마다 재생성 |
| `app_ver` | string | `"1.2.0"` | 빌드별 비교의 근거. **없으면 A/B 판정이 불가능하다** |
| `platform` | string | `"android"` | |
| `country` | string | `"PH"` | ⚠ **스토어/네트워크가 주는 국가 코드만.** 좌표·IP 저장 금지 |
| `device_tier` | string | `"low"\|"mid"\|"high"` | 성능 이슈를 기기 등급과 교차 분석하기 위함 |

### 3.2 이벤트 정의

| 이벤트 (`ANALYTICS_EVENTS`) | 언제 | 필수 속성 | 답하는 질문 |
|---|---|---|---|
| `session_start` | 앱 포그라운드 진입 | `is_first_open`(bool), `days_since_install`(int) | Q1·Q3 |
| `run_start` | 런 시작 순간 | `stage_id`, `run_index_in_session`(int), `sanctum_lv`(obj), `equip`(배열) | Q2 |
| **`run_end`** | 런 종료 (사망·클리어·포기 전부) | **`reason`**(`"death"\|"clear"\|"quit"`), **`duration_s`**(int), **`phase`**(0~6), `level`, `kills`, `gold`, `dmg_dealt`, `dmg_taken`, `awakenings`(배열), `weapons`(배열) | ★ **Q2 전부.** 이 게임에서 가장 중요한 단일 이벤트 |
| `level_up` | 레벨업 | `level`, `t_s`(경과초) | 레벨업 리듬 (목표 18~22회 / 정본 GDD §1) |
| `pact_choice` | 카드 선택 | `level`, `chosen`(축복id), `offered`(id 3개), `toll_tag`, `rerolled`(bool), `skipped`(bool), `decide_ms` | 카드 밸런스. **`offered`가 있어야 픽률(=선택수/제시수)이 계산된다** |
| `awakening` | 각성 발동 | `tag`, `t_s`, `level`, `nth`(1\|2) | ★ 각성 발동률·발동 시점 |
| `boss_engage` | 보스 등장 | `boss_id`, `player_hp_pct` | 보스전 진입률 |

| `ad_request` | 광고 요청 | `placement`, `ready`(bool) | **필값(fill rate)** — 광고가 "안 뜨는" 문제의 유일한 단서 |
| `ad_rewarded` | 보상 지급 완료 | `placement`, `reward_type`, `ecpm_hint`(있으면) | Q4 |
| `iap_purchase` | 결제 성공 | `sku`, `price_local`, `currency`, `first_purchase`(bool) | Q4 |

> 🔧 **구현 계약과의 불일치 1건 (패치 필요).**
> `FE/src/analytics/index.js`의 주석은 상수명을 **`EVENTS`** 로 적었으나 실제 export는 **`ANALYTICS_EVENTS`** 다.
> 주석을 실제 이름에 맞춰 고치는 편이 안전하다(호출부가 주석을 보고 짜면 즉시 깨진다).
> 이 파일은 다른 담당 영역이므로 여기서는 **제안만 남긴다.**

### 3.3 이벤트 설계 규칙

| # | 규칙 | 이유 |
|---|---|---|
| E1 | **`run_end`는 어떤 경우에도 1회 발화한다.** 크래시·백그라운드 강제 종료 포함 | 이게 빠지면 **이탈 분석에서 "가장 나쁜 런"만 통째로 사라진다.** 생존 편향이 생긴다 |
| E2 | 앱 백그라운드 전환 시 `run_end{reason:"quit"}`을 즉시 기록하고 로컬 큐에 남긴다 | 모바일에서 종료는 대부분 "돌아오지 않음"이다 |
| E3 | **속성에 자유 문자열을 넣지 않는다.** 전부 열거형 또는 숫자 | 오타 하나가 코호트를 쪼갠다 |
| E4 | 실패해도 절대 throw 하지 않는다 (계약에 이미 명시) | **분석이 게임을 죽이는 것이 최악**이다 |
| E5 | 오프라인 큐잉 + 다음 실행 시 전송. 큐 상한 **500건**, 초과 시 오래된 것부터 폐기 | 완전 오프라인 게임이므로 전송 실패가 정상 상태다 |
| E6 | **개발 빌드와 소프트런치 빌드의 데이터를 절대 섞지 않는다** (`app_ver` + 별도 프로젝트 키) | 내 자가 플레이 200판이 D1을 왜곡한다 |

### 3.4 ★ 이벤트만으로는 절대 알 수 없는 것

> 데이터는 **"무엇이 일어났는가"** 만 답한다. **"왜"** 는 답하지 않는다.

| 알 수 없는 것 | 대신 쓸 수단 |
|---|---|
| 3:00에 왜 그만두는가 | 스토어 리뷰 정독 · Discord/Reddit 1:1 · 지인 관찰 플레이 |
| 각성이 "시원한가" | ⚠ **끝까지 데이터로 답이 안 나온다.** 발동률은 측정되지만 **쾌감은 측정되지 않는다** |
| 카드 딜레마가 성립하는가 | `pact_choice.decide_ms` 분포가 간접 신호 — **고민 없이 고르면 딜레마가 없는 것** |

> `decide_ms`가 **중앙값 1.5초 미만**이면 카드가 "고민할 만하지 않다"는 뜻이다.
> 정본 GDD §1은 카드 선택에 **3~6초**를 상정했다. 이 괴리는 밸런스 문제가 아니라 **설계 실패 신호**다.

### 4.1 광고 지점 설계 — 리텐션을 먹지 않는 형태로만

> **원칙(구현 계약에 이미 명시): 유저가 스스로 누른 것만 보상형으로 띄운다.**
> 강제 전면광고는 ARPDAU를 즉시 올리고 리텐션을 늦게 깎는다. **그 시차가 함정이다.**

## 5. ★ 개인정보 — 방침 개정이 분석 도입의 선행 조건이다

### 5.1 현재 상태와 그 결과

**`privacy/index.html`은 현재 "아무것도 수집하지 않는다"고 명시하고 있다.** 실측 확인:

> "…수집하지 않습니다." / "수집·요구·전송하지 않습니다." /
> "수집하는 정보가 없으므로 제공·위탁·판매할 정보도 존재하지 않습니다."

**분석 SDK와 광고 SDK를 넣는 순간 이 문장은 거짓이 된다.**

| 무엇이 깨지는가 | 결과 |
|---|---|
| 개인정보 처리방침 | **허위 고지.** 국내 개인정보보호법 위반 소지 |
| **Play Console 데이터 안전(Data Safety) 양식** | 현재 "데이터 수집 안 함" 신고와 불일치 → **허위 신고는 앱 정지·삭제 사유** |
| App Store **App Privacy** 질문지 | 동일 |
| 광고 SDK | 광고 식별자·기기 정보를 수집한다. **"수집 없음"과 양립 불가** |

> 🚨 **순서를 반드시 지킨다: 방침 개정 → 스토어 신고 갱신 → SDK 도입 → 배포.**
> SDK를 먼저 넣고 방침을 나중에 고치면, **그 사이에 나간 빌드가 전부 허위 신고 상태**다.
> 이건 되돌릴 수 없다 — 이미 설치된 유저에게 소급 고지할 수단이 없다.

### 5.2 수집 원칙 (이 선을 넘지 않는다)

| 수집한다 | 수집하지 않는다 |
|---|---|
| **기기 로컬 생성 익명 UUID 1개** | 이름·이메일·전화번호·계정 |
| 게임 플레이 이벤트 (§3.2) | 정확한 위치(좌표), IP 저장 |
| 앱 버전 · OS 버전 · 기기 등급 | 연락처·사진·파일 접근 |
| 스토어/네트워크가 주는 **국가 코드** | 광고 ID를 자체 저장 (SDK 내부 사용은 SDK 고지 범위) |
| 구매 영수증 검증 정보 | 다른 앱 목록 |

> **UUID는 기기 로컬 생성이고 어떤 계정과도 연결되지 않는다.** 앱을 지우면 끊긴다.
> 이 점이 "익명"이라고 말할 수 있는 근거이며, **방침에도 그렇게 적어야 한다.**

### 5.3 개정 문구 제안

> ⚠️ `privacy/` 디렉토리는 **다른 담당 영역**이다. 아래는 **문구 제안**이며, 실제 반영은 그쪽에서 한다.
> ⚠ 이 문구는 **법률 자문이 아니다.** 수익화·전 세계 배포 시점(M5~M6)에는 검토를 받는 편이 안전하다.

