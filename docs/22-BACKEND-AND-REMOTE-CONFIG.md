# 22. 백엔드 & 원격 설정

> **문서 지위: 정본(CANON).** 서버 쪽 판단의 최종 출처.
> 구현은 `FE/src/monetization/remoteConfig.js`, 스키마 정본은 `FE/src/data/remote-defaults.json`,
> 분석 전송 계층은 `FE/src/analytics/queue.js` 다.

---

## 0. 결론 먼저

# **게임 서버를 만들지 않는다.**

만드는 것은 **정적 파일 1개(원격 설정 JSON)** 와 **엔드포인트 1개(분석 수집)** 뿐이다.
그 둘도 **없으면 게임이 100% 정상 동작하도록** 설계돼 있다.

| 만드는 것 | 형태 | 없으면 |
|---|---|---|
| 원격 설정 | **정적 JSON 파일 1개** (CDN) | 로컬 기본값으로 동작. 아무 일도 안 일어난다 |
| 분석 수집 | **POST 엔드포인트 1개** | 전송 0건. 게임은 정상, **지표만 없다** |
| 영수증 검증 | **RevenueCat 위탁** (직접 만들지 않음) | 무검증. §5 의 리스크를 감수 |
| 계정 · 클라우드 세이브 · 랭킹 | **만들지 않는다** | — |

### 0.1 왜 이렇게까지 줄이는가

1. **1인 개발 6개월에서 서버는 개발 비용이 아니라 *운영* 비용이다.** 서버가 생기는 순간
   가동률·백업·비밀키 로테이션·장애 대응이 매주의 일이 된다. 그 시간은 게임에서 나온다.
2. **서버가 있으면 서버가 죽었을 때 게임이 죽는다.** 오프라인 싱글플레이 게임에서
   이건 순수한 손해다. `03-GDD-CORE` §9 가 이미 백엔드 없음을 확정했다.
3. **랭킹 보드는 컷 확정**이다(`21` §4.3). 대체안은 `25-GROWTH-AND-UA.md` §5.

> ⚠ **단, "지표 없음"은 감수할 수 없다.** `27` §10 의 소프트런치 게이트(D1 28%, D7 8%)는
> 측정 없이는 판정 자체가 불가능하다. **§4 의 엔드포인트 하나는 소프트런치의 전제 조건이다.**

## 1. 원격 설정 — 무엇을 열고 무엇을 절대 열지 않는가

### 1.1 제1원칙: 원격은 **덮어쓰기일 뿐**이다

`remote-defaults.json` 만으로 게임이 100% 돌아야 한다. 그래서 `initRemoteConfig()` 는
**네트워크를 기다리지 않는다** — 캐시/기본값으로 즉시 반환하고 갱신은 백그라운드에서 한다.

```
부팅 ──► 기본값(즉시)  ──►  캐시 덮어쓰기(로컬 읽기, ~1ms)  ──►  네트워크 덮어쓰기(백그라운드)
        ↑ 여기서 이미 게임은 완전히 동작한다
```

> **`await` 로 네트워크를 기다리면 스플래시가 최대 4초 늘어난다.** 그 4초는 D1 을 직접 깎는다.
> 전부 원격으로 열면 서버 없이는 게임이 안 켜진다 — 그 상태를 만들지 않는 것이 이 설계의 전부다.

### 1.2 제2원칙: **서버를 믿지 않는다**

오타 하나로 `balance.goldMult` 에 `"1"`(문자열)이나 `1e9` 가 오면 경제가 즉사한다.

| 방어 | 구현 |
|---|---|
| 타입 강제 | `coerce()` — `bool/int/num/str` 만. 다른 타입은 **값을 버리고 기본값 유지** |
| 범위 clamp | 모든 수치 키에 `min`/`max` 필수 |
| 길이 제한 | 문자열은 `maxLen` 으로 자른다 |
| **알 수 없는 키는 버린다** | 구버전 앱이 신규 키를 만나도 안전 |
| 누락 키는 기본값 | 원격이 키를 빼먹어도 그 키만 기본값으로 남는다 |

### 1.3 ★ 스칼라만 연다 — 배열·객체는 열지 않는다

**모양이 틀어지면 clamp 로 막을 방법이 없기 때문**이다. `{v, t, min, max}` 스키마가
검증할 수 있는 것은 스칼라뿐이다. 문자열 목록이 필요하면 **CSV 문자열**로 보낸다(`shop.hiddenSkus`).
이것은 우아하지 않지만 **의도적인** 우회다.

### 1.4 원격 대상이 **아닌** 것 — 이 목록이 안전의 절반이다

| 대상 | 왜 열지 않는가 |
|---|---|
| 세이브 스키마 / 마이그레이션 | 원격 값 하나로 **복구 불가능한 데이터 손상**이 난다 |
| `sanctum.json` 비용·효과 | 결제 상품 가치와 직결. 흔들면 **이미 산 유저가 사후에 손해**를 본다(`20` §2.3) |
| 상품 가격 | 스토어 콘솔이 유일한 정본. 앱이 가격을 그리면 환율·세금이 어긋난다(`20` §3.3) |
| 무기/적/축복/대가/각성 테이블 | 밸런스는 `balance.*` **전역 배율 5개로만** 흔든다 |
| **강제 업데이트 최소 버전** | ↓ §1.5 |

### 1.5 ⚠ 강제 업데이트 스위치를 두지 않는 이유

원격 값 하나로 **전 유저의 앱을 잠글 수 있는 스위치**다. 오타 한 번, CDN 캐시 사고 한 번으로
전 유저가 게임을 못 켜게 된다. 되돌리려면 다시 원격이 필요한데, 그 원격이 죽어서 생긴 사고라면
**복구 경로가 없다.** 서버 운영이 안정된 뒤에(그리고 킬스위치의 킬스위치를 만든 뒤에) 도입한다.

## 2. 원격 설정 — 배포 형태와 운영

### 2.1 형태: **정적 JSON 1개.** SDK 도, 계정도, 비용도 없다

```
https://<cdn>/bloodsworn/rc/v1.json     ← 이 파일 하나가 전부다
```

`remoteConfig.js` 의 기본 fetcher 는 이 URL 을 GET 해서 JSON 을 받는 것뿐이다.
`initMonetization({ remoteConfigUrl })` 에 URL 을 주지 않으면 **원격 기능 자체가 꺼진다** —
소프트런치 이전의 정상 상태다.

| 후보 | 비용 | 장점 | 단점 |
|---|---|---|---|
| **GitHub Pages / raw** | 무료 | 계정 이미 있음. git 이 곧 변경 이력·롤백 | 캐시 헤더 제어 불가(raw 는 ~5분 고정), SLA 없음 |
| **Cloudflare Pages** | 무료 | 캐시 헤더 제어, 즉시 무효화, 전 세계 CDN | 계정 1개 추가 |
| **S3 + CloudFront** | ~$1/월 | 완전 제어 | 설정이 가장 무겁다 |
| Firebase Remote Config | 무료 티어 | 조건부 타깃팅(국가·버전·%), A/B | SDK 추가 = 앱 용량·프라이버시 매니페스트·데이터 안전 양식 항목 증가 |

> **권고: Cloudflare Pages.** 소프트런치 규모에서 유의미한 유일한 차이가 **캐시 무효화 속도**다.
> 잘못된 값을 밀었을 때 6시간을 기다려야 하는지 5분이면 되는지는 사고 대응에서 큰 차이다.
> **Firebase Remote Config 는 필요할 때 `fetcher` 옵션으로 갈아끼운다** —
> `initRemoteConfig({ fetcher })` 가 이미 그 구멍이고, `remoteConfig.js` 를 고칠 필요가 없다.
> A/B 테스트나 국가별 타깃팅이 실제로 필요해지기 전까지는 SDK 를 늘리지 않는다.

### 2.2 페이로드 포맷

```json
{
  "configVersion": 7,
  "values": {
    "ads.sanctumOffering.perDay": 3,
    "shop.promoText": "첫 서약자의 궤 — 72시간",
    "balance.bossHpMult": 0.92
  }
}
```

- **바꾸는 키만 적는다.** 빠진 키는 앱의 기본값이 그대로 살아남는다(§1.2).
- `values` 를 감싸지 않고 평면 객체로 보내도 받는다(`normalize()` 가 둘 다 처리한다).
- `configVersion` 은 캐시 기록용이며 동작에 영향을 주지 않는다. 운영자가 "어느 판이 나갔나"를 보기 위한 것이다.

### 2.3 캐시와 갱신 주기

| 항목 | 값 | 근거 |
|---|---|---|
| 앱 측 TTL | **6시간** (`_fetch.ttlSec = 21600`) | 하루 3~4회 세션에서 1~2회 갱신. 서버 부하 0 에 가깝다 |
| 요청 타임아웃 | 4초 | 그 이상 기다릴 이유가 없다. 실패 = 캐시 유지 |
| CDN `Cache-Control` | `public, max-age=300` | 5분. 사고 시 롤백 반영 속도를 결정한다 |
| 실패 시 | 조용히 무시 | 오프라인은 **정상 경로**다. 재시도 루프를 돌리지 않는다 |

⚠ 앱은 `cache: "default"` 로 요청한다. `no-store` 를 걸면 CDN 이득이 사라진다.

### 2.4 배포 절차 (5분)

1. 로컬에서 `v1.json` 을 고친다. **`remote-defaults.json` 의 스키마에 있는 키인지 눈으로 확인한다** —
   없는 키는 앱이 조용히 버리므로 "밀었는데 아무 일도 안 일어남"이 된다.
2. `configVersion` 을 +1 한다.
3. 배포 → 5분 뒤 CDN 반영.
4. **디버그 HUD 에서 `monetizationDebugState().config.source === "network"` 를 확인한다.**
   `"cache"` 나 `"default"` 면 반영되지 않은 것이다.

### 2.5 롤백

**`v1.json` 을 이전 커밋으로 되돌리는 것이 전부다.** 최악의 경우 파일을 `{"configVersion":0,"values":{}}`
로 비우면 전 유저가 로컬 기본값으로 돌아간다 — 이것이 항상 존재하는 안전한 착륙 지점이다.

> ★ **이 설계의 핵심 이득이 여기 있다.** 원격 설정의 가장 나쁜 실패조차
> "기본값으로 돌아감"이지 "게임이 안 켜짐"이 아니다. §1.5 의 강제 업데이트 스위치를 두지 않는 것도
> 그 성질을 깨지 않기 위해서다.

### 2.6 원격으로 실제로 하게 될 일 3가지

| 상황 | 조작 | 앱 업데이트 |
|---|---|---|
| 광고 배치가 지표를 해친다 | `ads.<placement>.enabled = false` | 불필요 |
| 보스가 너무 어렵다(D1 이탈) | `balance.bossHpMult = 0.9` | 불필요 |
| 스타터 팩이 안 팔린다 | `shop.starterWindowHours` 조정, `shop.promoText` | 불필요 |
| 분석 부하/비용이 크다 | `analytics.sampleRate = 0.3` | 불필요 |

⚠ `balance.*` 를 흔들 때는 **`app_ver` + 원격 `configVersion` 을 이벤트에 함께 실어야** 한다.
안 그러면 지표 변화가 밸런스 때문인지 앱 업데이트 때문인지 영원히 구분할 수 없다.

## 3. 분석 백엔드 — **소프트런치의 전제 조건**

`analytics/queue.js` 는 `POST <endpoint>` 로 `{ events: [...], dropped: n }` 을 보내는 것이 전부다.
**엔드포인트가 없으면 큐에 쌓지도 않는다**(네트워크 전송 0건이 기본 상태).

### 3.1 선택지 비교

| 후보 | 비용 | 코드 변경 | 리텐션 코호트 | 판정 |
|---|---|---|---|---|
| **Cloudflare Worker + D1/R2** | 무료 티어로 충분 | `endpoint` 문자열 1개 | 직접 SQL | **권고** |
| **GameAnalytics** | 무료 | SDK 추가 또는 REST 어댑터 | **내장** (D1/D7 대시보드) | 유력 대안 |
| Firebase Analytics | 무료 | SDK 추가 | 내장 | 프라이버시 매니페스트 대상 SDK 증가(`27` §8) |
| 자체 VPS | $5/월~ | 서버 운영 발생 | 직접 | **기각** — §0.1 |
| 없음 | 0 | 0 | 없음 | **소프트런치 불가** |

> **권고 순서: ① GameAnalytics(가장 빠른 답) → ② Cloudflare Worker(원본 데이터 보유).**
> 둘을 동시에 가도 된다. `queue.js` 는 엔드포인트 1개만 알지만, Worker 가 GameAnalytics 로
> 릴레이하면 클라이언트 코드를 늘리지 않고 둘 다 얻는다.
>
> ★ **판정 기준은 "리텐션 코호트를 내가 계산할 수 있는가"** 다. D1/D7 은 `27` §10 의 출시 게이트이고,
> 이걸 직접 계산하려면 `uid × 첫 실행일 × 활동일` 테이블이 필요하다. 이벤트를 파일에 쌓아두기만 하면
> 나중에 그 SQL 을 짜는 하루가 반드시 온다. **그 하루를 소프트런치 전에 미리 쓰는 편이 낫다.**

### 3.2 Cloudflare Worker 수집기 — 최소 사양

```
POST /ingest
  body: { events: [{ n, t, s, u, p }], dropped }
  응답: 204 (본문 없음)
```

| 요구사항 | 이유 |
|---|---|
| **CORS 허용** (`capacitor://localhost`, `https://localhost`, `file://`) | 안 열면 안드로이드/iOS WebView 요청이 전부 막힌다. **가장 흔한 첫 실패** |
| 본문 크기 상한 (예: 256KB) | 조작된 클라이언트 방어 |
| **IP 를 저장하지 않는다** | `privacy/` 표와 데이터 안전 양식에 IP 수집을 적지 않으려면 정말로 저장하면 안 된다 |
| 200~204 외 응답은 재시도 유발 | 클라이언트가 큐를 되돌리고 다음 기회에 다시 보낸다 |
| `n`(이벤트명) 화이트리스트 검증 | 쓰레기 데이터로 테이블이 오염되는 것을 입구에서 막는다 |

⚠ **`keepalive: true` 로 보내므로 요청 본문이 64KB 를 넘으면 브라우저가 거부한다.**
`batchSize` 기본 20, 1회 전송 상한 100건 설계는 이 한계 안에 들어가기 위한 것이다.

### 3.3 이벤트가 실제로 나가기 시작하면 지켜야 할 것

- **개발 빌드와 소프트런치 빌드의 데이터를 절대 섞지 않는다.** 엔드포인트를 나누거나
  `app_ver` 로 필터한다. 자가 플레이 200판이 D1 을 왜곡한다(`21` §3.3 E6).
- `analytics.sampleRate` 는 **기기 단위 고정 샘플링**이다(anonId 해시). 매번 주사위를 굴리면
  같은 유저가 어떤 날은 잡히고 어떤 날은 안 잡혀 **리텐션 계산이 통째로 틀어진다.**
- 큐 상한 500건 / 세션 상한 300건 / 초당 20건. **60fps 루프에서 `track()` 을 부르면 조용히 잘린다.**

## 4. 영수증 검증 — 서버를 만들지 않기로 한 것의 대가

### 4.1 사실: **클라이언트만으로는 영수증을 검증할 수 없다**

`entitlements.js` 의 `owned` 는 localStorage/Preferences 에 있는 **캐시이지 증거가 아니다.**
루팅된 기기에서 파일을 고치면 `hasEntitlement("removeAds")` 는 true 가 된다. 이건 막을 수 없다.

### 4.2 세 가지 선택지

| 선택지 | 검증 | 비용 | 운영 부담 |
|---|---|---|---|
| **RevenueCat** (`iap.js` 기본 어댑터) | **서버 측 검증 + 소유권 동기화** | 월 매출 $2,500 까지 무료 | 대시보드 설정만 |
| 자체 검증 서버 | 직접 (Play Developer API / App Store Server API) | 서버 비용 + 개발 | **높다** — 키 로테이션, 장애 대응 |
| 무검증 (로컬 원장만) | 없음 | 0 | 0 |

> **권고: RevenueCat.** 이유는 "서버를 세우지 않고 서버 측 검증을 얻는" 유일한 선택지라서다.
> 기기 변경·재설치 복구도 자동으로 딸려 온다(`getCustomerInfo()` → `mergeRestored()`).

### 4.3 ★ 그런데 무검증이어도 **치명적이지 않은** 이유

이 게임에는 **랭킹·PvP·거래·서버 경제가 없다.** 위조로 얻을 수 있는 것은
`removeAds` 와 골드뿐이고, 그 결과는 **자기 세이브 안에서만** 일어난다.

| 위조 대상 | 피해자 | 우리 손해 |
|---|---|---|
| `removeAds` | 없음 | 광고 수익 일부 (그 유저는 어차피 안 샀을 확률이 높다) |
| 골드 | 없음 | 골드 팩 매출 일부 |
| 다른 유저의 경험 | **없음** (경쟁 요소 자체가 없다) | — |

> **그래서 순서를 이렇게 정한다: 검증 없이 소프트런치를 시작해도 된다.
> 단 `20` §2 의 침범 금지선을 지켰기 때문에 그렇다** — 만약 P2W 상품을 팔았다면
> 위조는 게임 밸런스 사고가 되고, 검증은 선택이 아니라 필수가 됐을 것이다.
> **설계 결정이 인프라 요구사항을 낮춘 사례다.**

### 4.4 그럼에도 지켜야 할 3가지

1. **환불된 결제를 되돌릴 방법이 없다.** RevenueCat 을 쓰면 `getCustomerInfo()` 가
   부팅마다 소유권을 맞춰 주므로 자동 회수된다. 무검증이면 회수 불가 — 감수 항목이다.
2. **`mergeRestored()` 는 추가만 하고 삭제하지 않는다.** 오프라인 복원 실패로 산 권리가
   증발하는 것이 위조보다 훨씬 나쁜 사고이기 때문이다. 이 비대칭은 의도된 것이다.
3. **소모성 골드는 지급 즉시 세이브에 반영**한다(`20` §5.3).

## 5. 🚨 Play Billing 8+ (2026-08-31) — 이 프로젝트의 최대 기술 불확실성

`27` §0 이 확인한 사실: **2026-08-31 부터 신규 앱과 모든 업데이트가 Play Billing Library 8 이상을 요구한다**
(Play Console 에서 2026-11-01 까지 연장 신청 가능). Billing 8 은 `queryPurchaseHistory()`,
`querySkuDetailsAsync()`, `enablePendingPurchases()` 를 제거했고, 8.1.0 은 `minSdkVersion 23` 을 요구한다.

### 5.1 무엇이 위험한가

**커뮤니티 Capacitor IAP 플러그인은 역사적으로 Billing 메이저 버전을 늦게 따라간다.**
플러그인이 Billing 7 을 감싸고 있으면 **AAB 제출이 조용히 거부된다** — 코드가 잘 돌아가는데도 그렇다.
이건 "나중에 고치면 되는" 종류가 아니라 **출시 자체를 막는** 종류다.

### 5.2 그래서 `iap.js` 를 어댑터 패턴으로 만들었다

```js
registerIapAdapter({ name, init, getProducts, purchase, restore })
```

이 구멍이 있는 이유가 정확히 이 마감이다. 결제 SDK 를 갈아끼울 때 **`iap.js` 를 고치지 않는다.**
어댑터 계약:

| 메서드 | 반환 |
|---|---|
| `init(opts)` | — (실패 시 throw → 다음 후보로 넘어간다) |
| `getProducts(skus)` | `[{ sku, priceString, price, currency, storeTitle }]` |
| `purchase(sku)` | `{ ok, receipt?, reason?, entitlements?: string[] }` |
| `restore()` | `string[]` (보유 entitlement 키) |

### 5.3 ★ 선결 과제 — 다른 무엇보다 먼저 답해야 하는 질문

> **"우리가 쓸 IAP 플러그인의 현재 릴리스가 감싸는 Play Billing Library 버전은 몇인가?"**

이건 문서로 추정할 문제가 아니라 **직접 확인해야 하는 사실**이다. 확인 절차:

1. 후보 플러그인의 GitHub 릴리스 노트에서 Billing 버전 언급을 찾는다.
2. 확실한 방법: 설치 후 `FE/android/` 에서 `./gradlew :app:dependencies` 를 돌려
   **`com.android.billingclient:billing` 의 실제 해석 버전**을 눈으로 확인한다. 이게 유일한 증거다.
3. 8 미만이면 → §5.4 의 대안으로 간다.

⚠ RevenueCat 은 자체 Android SDK 가 Billing 을 감싸므로 **RevenueCat Capacitor 플러그인의 버전이
곧 Billing 버전을 결정한다.** RevenueCat 은 상업 벤더라 대응이 대체로 빠르지만 **가정하지 말고 확인할 것.**

### 5.4 대안 3개 (위에서부터 시도한다)

| # | 대안 | 비용 | 비고 |
|---|---|---|---|
| A1 | 플러그인을 Billing 8+ 지원 버전으로 올린다 | 낮음 | 첫 번째 시도 |
| A2 | **Play Console 에서 2026-11-01 까지 연장 신청** | 0 | `27` §0. **오늘 신청 가능하면 지금 하는 것이 옳다** — 쓰지 않아도 손해가 없다 |
| A3 | 얇은 자체 Capacitor 플러그인을 작성해 Billing 8 을 직접 감싼다 | **높음** (수일) | `registerIapAdapter()` 로 끼운다. 최후 수단 |

> ★ **A2 를 먼저 확보하라.** 기술 조사보다 빠르고, 실패해도 잃는 것이 없으며,
> A1/A3 판단에 필요한 시간을 산다. `27` §10 의 "이번 주" 항목이 이것이다.

### 5.5 iOS 는 지금 결정하지 않는다

`27` §6 의 결론대로 iOS 는 뒤로 미룬다. 다만 `iap.js` 어댑터 계약이 플랫폼 중립이므로
StoreKit 2 어댑터를 나중에 끼우는 데 구조적 장애물은 없다.
`shop.json` 의 `storeIdMapping` 이 **양 플랫폼에서 SKU 문자열을 동일하게** 쓰도록 못 박은 것도 이 때문이다 —
다르면 영수증 대조 로직이 두 벌이 된다.

## 6. 개인정보 — 서버가 없어도 의무는 있다

| 의무 | 구현 |
|---|---|
| **삭제 요청** | 옵션 → "분석 데이터 삭제" = `resetAnalyticsIdentity()` (익명 ID 재발급 + 큐 폐기) |
| **동의 철회** | 옵션 → "광고 동의 다시 설정" = `resetAdConsent()` (`20` §6.1) |
| **수집 항목 공개** | `privacy/` 의 표는 **실제로 나가는 필드와 1:1** 이어야 한다 |
| 전송 중 암호화 | HTTPS 전용. `credentials: "omit"`, `referrerPolicy: "no-referrer"` |

### 6.1 우리가 절대 수집하지 않는 것 — 코드로 강제된다

`analytics/index.js` 의 `FORBIDDEN_KEYS` 정규식이 `name|email|phone|addr|lat|lng|ip|uid|adid|idfa|imei|token`
등을 **props 에서 자동으로 제거**한다. 실수로 넣어도 나가지 않는다.

⚠ **다만 Google Mobile Ads SDK 는 우리와 무관하게 IP·광고 ID 를 수집한다.**
`27` §5 대로 **Play 데이터 안전 양식에는 SDK 수집분도 우리가 신고**해야 한다.
"우리 코드는 수집하지 않는다"는 신고 근거가 되지 않는다. **허위 기재는 업데이트 차단·앱 삭제 사유다.**

### 6.2 저장 키 4개 — 무엇이 지워지고 무엇이 남는가

| 키 | 내용 | "저장 데이터 삭제" | "분석 데이터 삭제" |
|---|---|---|---|
| `bloodsworn.save.v1` | 진행도 | **지워진다** | 남는다 |
| `bloodsworn.ent.v1` | 구매 권리·미지급 원장 | **남는다** | 남는다 |
| `bloodsworn.adcap.v1` | 광고 상한 카운터 | 남는다 | 남는다 |
| `bloodsworn.evq.v1` + `bloodsworn.aid.v1` | 분석 큐·익명 ID | 남는다 | **지워진다** |
| `bloodsworn.rc.v1` | 원격 설정 캐시 | 남는다 | 남는다 |

## 7. 실패 모드 매트릭스 — 전부 "게임은 정상"이어야 한다

| # | 사고 | 게임 | 수익화 | 지표 | 대응 |

| S4 | 분석 큐 500건 초과 | **정상** | 정상 | 오래된 것부터 유실 | 없음(의도된 설계) |

> **이 표에서 "게임" 열에 정상 외의 값이 하나라도 생기면 그건 설계 위반이다.**
> 새 기능을 붙일 때마다 이 표에 행을 추가하고 같은 답이 나오는지 확인한다.

### 7.1 ⚠ 실제로 발견된 상호작용 위험 2개

| # | 문제 | 왜 |
|---|---|---|
| X1 | **보상형 광고가 뜨면 안드로이드에서 WebView 가 백그라운드로 간다.** `platform.js` 의 `handleBackground()` 가 이를 "앱 이탈"로 오인해 일시정지 모달을 띄운다 | 광고를 닫고 돌아왔을 때 엉뚱한 일시정지 화면이 떠 있다 |
| X2 | **부활 오버레이가 안드로이드 back 으로 닫힌다.** `handleBack()` 은 `pact.open` 만 방어한다 | 결정 대기 중 back → 오버레이만 사라지고 런이 멈춘 채 남는다 |

둘 다 "광고 중"을 나타내는 플래그 하나로 해결된다. 패치는 인수인계 보고서에 있다.

## 10. 확인하지 못한 것 (사실로 취급하지 말 것)

1. **Capacitor IAP/AdMob 플러그인의 현재 Billing / GMA SDK 버전** — §5.3 의 절차로 직접 확인할 것.
2. **RevenueCat 무료 티어 한도의 현재 수치** — 인용값은 변할 수 있다. 계약 전 원문 확인.

5. **`keepalive` 본문 64KB 한계가 Android WebView 에서 동일한지** — 명세상 그렇지만 실측하지 않았다.
