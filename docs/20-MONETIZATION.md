## 1. ★ 이 게임의 수익화가 반드시 답해야 하는 질문

BLOODSWORN 의 유일한 차별화는 **"대가를 치르는 선택"** 이다(`04-PACT-SYSTEM.md`).
레벨업이 이득이 아니라 **딜레마**이기 때문에 재미있다.

> **그러므로 이 게임에서 가장 위험한 수익화는 광고 노출량이 아니라 "대가를 돈으로 지우는 것"이다.**
> 대가를 지울 수 있게 되는 순간, 이 게임은 대가 시스템이 없는 평범한 뱀서 클론이 된다.
> 그때 남는 경쟁력은 0 이다 — 그 시장에는 이미 완성도가 훨씬 높은 무료 게임이 수십 개 있다.

즉 **P2W 금지는 윤리 규범이 아니라 제품 생존 조건**이다. §2 는 취향이 아니라 사양이다.

## 2. ★ 침범 금지선 (Forbidden Line) — 코드보다 먼저 읽는 절

`shop.json` 의 `_forbiddenForever` 배열이 이 절의 기계 판독본이다. 둘은 항상 일치해야 한다.

### 2.1 절대 팔지 않는 것 — 돈으로도, 광고로도

| # | 금지 대상 | 왜 |
|---|---|---|
| F1 | **인간성 회복 / 인간성 상한 증가** | 인간성은 **단방향 자원**이다(`04` §8, 회복 수단 없음). 회복을 파는 순간 「완전 흡혈귀화」가 "피할 수 있는 사고"가 되고, 후반 카드 선택의 무게가 통째로 사라진다 |
| F2 | **대가(Toll) 제거 · 약화 · 대가만 리롤** | 이 게임 그 자체를 파는 것이다. `04` §6.1 이 이미 "대가만 리롤"을 설계 차원에서 금지했다 |
| F3 | **각성 상한(런당 2개) 해제 · 각성 즉시 발동** | 각성은 3중첩을 **감수한 결과**다. 사면 각성이 보상이 아니라 구매 아이템이 된다 |
| F4 | **부활 횟수 상한 해제** | 런당 1회는 **결제자에게도 동일**하다. §4.2 참조 |
| F5 | **성소 상한 초과 강화 · 결제 전용 스탯** | 무과금 상한과 결제 상한이 같아야 "돈은 속도만 산다"가 사실이 된다 |
| F6 | **결제 전용 무기 · 축복 · 각성** | 콘텐츠 격차는 곧 밸런스 격차다 |
| F7 | **확률형 아이템(가챠) 일체** | 한국 확률 표시 의무, Apple `Loot Boxes` 연령 등급, Play 정책 — 1인 개발이 감당할 규제 표면이 아니다 |

### 2.2 팔아도 되는 것 — 판정 규칙 하나

> **"무과금 유저가 시간을 들이면 도달할 수 있는 같은 지점인가?"**
> **예 → 팔아도 된다(시간을 파는 것). 아니오 → 팔면 안 된다(승리를 파는 것).**

이 규칙 하나로 전부 판정된다. 골드 팩은 예(성소는 무과금도 10,930 골드면 만렙),
「영원한 서약」도 예(광고를 보면 같은 보상을 받는다), 인간성 회복은 아니오(도달 경로 자체가 없다).

### 2.3 상한 설계로 F5 를 강제한다 — 「골드 성궤」의 의미

성소 전체 완성에 필요한 골드 총액은 **10,930** 이다(`sanctum.json`).
최상위 골드 팩 `bs_gold_l` 은 **11,000 골드**다. 즉 **최상위 팩 하나로 성소가 끝난다.**

> 이것은 가격 실수가 아니라 **의도적 천장**이다. "더 팔 것이 없다"는 상태를 만들어
> 결제 압박의 상한을 카탈로그 구조로 못 박는다. 고래를 짜내는 설계가 구조적으로 불가능해진다.
> 성소가 끝난 유저에게 남는 상품은 **외형(cosmetic)** 뿐이며, 그것은 밸런스와 무관하다.

⚠ **따라서 성소 비용 테이블(`sanctum.json`)은 원격 설정 대상이 아니다.**
원격으로 비용을 올리면 이미 산 유저의 구매 가치가 사후에 깎인다(`remote-defaults.json` `_notRemote`).

## 3. IAP 카탈로그 — 6 SKU

정본은 `FE/src/data/shop.json` 의 `products` 배열이다. 아래 표는 그 근거다.
**가격은 참고값(`refPrice`)일 뿐이고, 앱이 화면에 그리는 가격은 스토어가 준 `priceString` 뿐이다**(§3.3).

| SKU | 종류 | 이름 | 지급 | 참고가 | 왜 이 상품인가 |
|---|---|---|---|---|---|
| `bs_eternal_pact` | 비소모성 | **영원한 서약** | `removeAds` 권리 | ₩5,500 | §3.1 — 이 게임에는 제거할 광고가 없다 |
| `bs_gold_s` | 소모성 | 핏빛 주머니 | 골드 1,200 | ₩1,500 | 최저 티어 진입점. 첫 결제 장벽을 낮춘다 |
| `bs_gold_m` | 소모성 | 핏빛 궤 | 골드 4,000 | ₩4,900 | `best` 뱃지. 앵커 상품 |
| `bs_gold_l` | 소모성 | 핏빛 성궤 | 골드 11,000 | ₩12,000 | §2.3 — 성소를 끝내는 천장 |
| `bs_starter` | 비소모성 | 첫 서약자의 궤 | 골드 4,000 + `removeAds` | ₩8,800 | 설치 후 **72시간 한정**. §3.2 |
| `bs_skin_ashen` | 비소모성 | 잿빛 진조(외형) | `skin_ashen` | ₩3,300 | 성소를 끝낸 유저에게 남는 유일한 상품 |

### 3.1 ★ 「영원한 서약」은 "광고 제거"가 아니다

**이 게임에는 강제 광고가 없다. 그러므로 제거할 대상이 없다.**
「영원한 서약」이 파는 것은 **"광고를 보지 않고도 같은 보상을 받는 권리"** 다.

| 항목 | 무과금 | 「영원한 서약」 |
|---|---|---|
| 부활 (런당) | 광고 시청 → 1회 | 즉시 → **1회 (동일)** |
| 골드 2배 (런당) | 광고 시청 → 1회 | 즉시 → **1회 (동일)** |
| 성소 헌납 (일) | 광고 시청 → 4회 | 즉시 → **4회 (동일)** |

> ★ **상한(perRun/perDay)은 결제자에게도 그대로 적용된다.** 이것이 F4/F5 를 지키는 방법이고,
> 구현상으로도 `ads.js` 의 `showRewarded()` 가 `hasEntitlement("removeAds")` 분기보다
> **`capBlockReason()` 을 먼저** 검사하는 이유다. 순서를 뒤집으면 결제자만 무제한이 된다.
>
> 즉 이 상품이 파는 것은 **30초 × N회의 시간과 번거로움**이지 게임 내 힘이 아니다. §2.2 판정 = 통과.

### 3.2 스타터 팩의 한정 표기는 **반드시 사실이어야 한다**

`bs_starter` 는 `window.afterFirstLaunchHours = 72` 다. 기준점은 `entitlements.firstLaunchAt`
(최초 실행 시각을 디스크에 못 박는다). 창이 지나면 `iap.js` 의 `visibleSkus()` 가 **정말로 목록에서 뺀다.**

> ⚠ **허위 카운트다운(지나도 계속 보이는 "한정")은 Play/App Store 양쪽에서 정책 위반이다.**
> 타이머를 그리는 UI 는 반드시 이 값을 읽어야 하고, 자체 타이머를 두면 안 된다.
> 창 길이는 `shop.starterWindowHours` 로 원격 조정 가능하지만 **소급 연장은 하지 않는다** —
> 이미 창을 놓친 유저에게 다시 띄우면 그게 곧 허위 표기다.

### 3.3 가격은 앱이 정하지 않는다

- 표시 문자열은 스토어가 준 `priceString` 만 쓴다. `refPrice` 는 **기획 문서용 참고값**이다.
- 스토어 응답이 없으면 `priceString` 은 빈 문자열이고, UI 는 "가격 불러오는 중"을 그린다.
  **가격을 모른 채 구매 버튼을 활성화하지 않는다.**
- 환율·부가세·지역 가격표가 나라마다 다르므로 앱이 계산한 가격은 **반드시 틀린다.**

### 3.4 `21-LIVEOPS` §4.2 "IAP 3종만" 과의 관계 — 이 문서가 우선한다

`21` §4.2 는 초안 시점의 3종 구성(`remove_ads` / `gold_pack_*` / `character_*`)을 적었다.
**이 문서가 정본이며, 다음 3가지를 의도적으로 바꿨다.**

| 항목 | `21` §4.2 초안 | **본 문서(정본)** | 이유 |
|---|---|---|---|
| `remove_ads` 에 "골드 상시 보너스" | 있음 | **없음** | 상시 골드 보너스는 무과금과 결제자의 진행 속도를 **영구적으로** 벌린다. §2.2 판정 = 실패 |
| `character_*` (캐릭터 해금 판매) | 있음 | **보류** | 캐릭터가 스탯을 바꾸면 F6 위반이다. 순수 외형만이면 팔 수 있으므로 `bs_skin_ashen` 으로 대체했다. 캐릭터 판매는 밸런스 동등성이 증명된 뒤에 재검토 |
| SKU 수 | 3 | **6** | 골드 팩 3티어 + 스타터 팩. 티어가 1개뿐이면 가격 탄력성을 읽을 수 없다 |

## 4. ★ 보상형 광고 배치 — 채택 3 / 기각 3

### 4.0 원칙 3개 (구현이 강제한다)

| # | 원칙 | 코드에서 강제되는 방식 |
|---|---|---|
| **P1** | **유저가 스스로 누른 것만 띄운다.** | `monetization` 모듈에 전면광고 API 자체가 **존재하지 않는다.** `showRewarded(placement)` 하나뿐이다 |
| **P2** | **광고 실패는 "보상 없음"이지 "진행 불가"가 아니다.** | 모든 실패 경로가 `{rewarded:false, reason}` 으로 즉시 반환된다. `reject` 하지 않는다 |
| **P3** | **상한은 성공한 시청만 깎는다.** | `ads.js` 는 `countImpression()` 을 보상 확정 이후에만 부른다. 로드 실패로 유저의 하루치 기회가 사라지면 그건 우리 잘못이다 |

> **P2 의 구체적 의미:** 비행기 모드에서 사망해도 게임은 결과 화면으로 정상 진행한다.
> 광고 버튼은 `isAdReady()` 가 false 면 **애초에 그려지지 않는다** — 눌렀는데 실패하는 경험을 만들지 않는다.

### 4.1 채택한 3개

| ID | 위치 | 보상 | 유저 비용 | 상한 | 원격 키 |
|---|---|---|---|---|---|
| **`revive`** | 사망 순간 | 그 자리 부활 (HP 50%, 무적 2초) | **인간성 −25** | **런당 1회** | `ads.revive.*` |
| **`gold_double`** | 결과 화면 | 이번 런 획득 골드 ×2 | 없음 | **런당 1회** | `ads.goldDouble.*` |
| **`sanctum_offering`** | 성소 화면 | 즉시 골드 120 | 없음 | **하루 4회** | `ads.sanctumOffering.*` |

전역 안전판: **`ads.dailyImpressionCap = 15`** (기기당 하루 총 노출 상한, 원격 조정 가능).

#### AD1 `revive` — 런 안에서 광고를 허용하는 **유일한** 자리

- **왜 여기인가:** 서바이버즈 장르에서 보상형 시청률이 가장 높은 지점이 "죽은 직후"다.
  6분 런의 5분 30초에 죽었을 때 유저가 느끼는 손실감이 광고 30초보다 훨씬 크기 때문이다.
- **★ 왜 이것이 P2W 가 아닌가 — 인간성 25를 값으로 치르기 때문이다.**
  광고로 대가를 *지우는* 것이 아니라 **대가를 더 사는 것**이다. 인간성 100 에서 시작해
  Epic 카드 2장이면 24 가 깎이는 게임에서 25 는 가볍지 않다. 부활한 런은
  「완전 흡혈귀화」(인간성 0)에 훨씬 가까워지고, 그 상태는 **유리한 것이 아니라 도전 과제**다(`04` §5.4).
  → 이 배치는 THE PACT 를 침식하지 않고 **오히려 밀어 넣는다.**
- **전제 조건 2개 (지키지 않으면 이 배치를 뺀다):**
  1. `requires.minHumanity = 25`. **인간성이 25 미만이면 버튼을 그리지 않는다.**
     인간성을 음수로 만들거나 0 에서 무료 부활을 주면 F1 위반이다.
  2. ⚠ **각성 「불사의 껍질」(FRAIL×3)의 부활과 합산해 런당 총 1회를 넘지 않는다.**
     각성이 준 부활을 이미 썼으면 광고 부활 버튼은 사라진다.
     이걸 안 지키면 광고가 각성의 가치를 직접 침식한다 — 그 각성을 목표로 대가를 모은 유저가 배신당한다.
- 상한 1회인 이유: 2회 이상이면 "런 길이"가 지표로서 무의미해지고(§7), 실력이 아니라 인내가 기록을 만든다.

#### AD2 `gold_double` — 밸런스에 개입이 **구조적으로 불가능한** 자리

- **왜 여기인가:** 런이 **이미 끝난 뒤**다. 인게임 상태에 아무 영향이 없고, 성소 진행 속도만 당긴다.
  §2.2 판정: 무과금도 런을 한 번 더 돌면 같은 골드에 도달한다 → **순수한 시간 단축.** 통과.
- 이 장르에서 가장 시청률이 높고 가장 안전한 표준 배치다. 논쟁의 여지가 없다.
- **★ 배치 규칙:** 버튼이 **[다시 하기] 를 가리거나 밀어내지 않는다.**
  `03-GDD-CORE` §12 의 "재시작 3초" 규칙이 광고 버튼보다 우선한다.
  광고를 무시하고 곧장 다시 시작하는 경로가 항상 한 번의 탭이어야 한다.

#### AD3 `sanctum_offering` — 런을 돌지 않고도 성소를 굴리는 자리

- **왜 여기인가:** 복귀 유저의 첫 세션을 붙잡는다. "오늘 5분밖에 없다"는 유저가
  런을 돌지 않고도 진행감을 얻는 유일한 경로다. 런 밖이라 게임 흐름을 끊지 않는다.
- **왜 하루 4회 · 120 골드인가 — 산수로 정했다.**
  4 × 120 = **하루 480 골드**. 성소 총액 10,930 대비 **4.4%**.
  → 광고만으로 성소를 다 채우려면 **약 23일**이 걸린다. 이 속도는 정상 플레이보다 느리다.
  즉 이 배치는 진행의 **보조**이지 대체가 아니며, 무과금 진행 곡선을 무너뜨리지 않는다.
  ⚠ 이 수치를 원격으로 올릴 때는 반드시 이 계산을 다시 한다. `perDay=10, amount=500` 이면
  하루 5,000 골드 = 이틀이면 성소 완성이고, 그 순간 `bs_gold_l` 의 존재 이유가 사라진다.

### 4.2 기각한 3개 — 그리고 그 중 하나는 `21` 을 뒤집는다

| ID | 형태 | 판정 | 이유 |
|---|---|---|---|
| `reroll_extra` | 계약서 리롤 +1 | **기각** | ↓ §4.3 |
| `toll_remove` | 대가 제거 / 약화 | **영구 기각** | F2 그 자체. 광고로도 돈으로도 팔지 않는다 |
| `interstitial_between_runs` | 런 사이 강제 전면광고 | **영구 기각** | ↓ §4.4 |

### 4.3 ★ `reroll_extra` 기각 — `21-LIVEOPS` §4.1 의 AD4 를 취소한다

`21` §4.1 은 **AD4 = "PACT 카드 리롤 +1회, 런당 2회"** 를 A/B 검증 대상으로 올려 두었다.
**본 문서는 이를 A/B 이전 단계에서 기각한다.** 근거는 세 가지다.

1. **딜레마의 소멸.** 리롤은 "나쁜 대가를 감당할 것인가"라는 질문을 "다시 뽑을 것인가"로 바꾼다.
   광고 리롤이 붙으면 유저의 최적 전략은 **원하는 축복이 나올 때까지 광고를 보는 것**이 된다.
   그 순간 `04` §2 의 "손해를 일부러 모으기 시작하는 전환점"은 영영 오지 않는다.
2. **각성 발동률의 직접 파괴.** 각성은 같은 태그 3중첩으로 발동한다(`04` §5.1).
   리롤이 늘어나면 유저는 대가 태그를 **분산**시켜 페널티를 희석하고, 3중첩이 안 만들어진다.
   `21` §4.1 스스로 "각성 발동률이 떨어지면 즉시 제거한다"고 적었다 —
   **떨어질 것이 예측되는 변경을 굳이 붙였다 떼는 비용을 지불할 이유가 없다.**
3. **이미 정본이 금지했다.** `04` §6.1 이 "대가만 리롤은 제공하지 않는다(딜레마가 사라짐)"고 못 박았고,
   전체 리롤이라 해서 논리가 달라지지 않는다. 리롤 횟수는 성소 **「재계약」**(런당 2→최대 5회)으로만 늘린다.
   그것은 **골드로 산 영구 업그레이드**이고, 골드는 무과금도 얻는다 — §2.2 판정 통과 경로가 이미 있다.

> **재검토 조건:** 소프트런치에서 `pact_choice.decide_ms` 중앙값이 3초를 크게 넘고
> 동시에 리롤 소진율이 100% 에 붙는다면, 그건 "리롤을 팔아라"가 아니라
> **"성소 「재계약」의 상한이 너무 낮다"** 는 신호다. 그때도 광고가 아니라 밸런스로 푼다.

### 4.4 강제 전면광고를 영구히 도입하지 않는 이유

- **시차가 함정이다.** 전면광고는 ARPDAU 를 **즉시** 올리고 리텐션을 **몇 주 뒤에** 깎는다.
  소프트런치 4주 창에서는 이득만 보이고 손해가 안 보인다. 그래서 "데이터로 판단"이 성립하지 않는다.
- 이 게임에서 런 사이는 **리텐션이 가장 얇은 구간**이다. `03-GDD-CORE` §12 의 "재시작 3초"는
  이 장르의 핵심 UX 이며, 전면광고는 그 규칙과 물리적으로 양립할 수 없다.
- **위 3개로 부족하면 광고를 늘릴 일이 아니라 게임을 고칠 일이다.**

### 4.5 빈도 상한 요약표 — 이 표가 `remote-defaults.json` 의 근거다

| 스코프 | 값 | 키 | 상한을 두는 이유 |
|---|---|---|---|
| `revive` 런당 | 1 | `ads.revive.perRun` (max 3) | 2회 이상이면 런 길이 지표가 무의미해진다 |
| `gold_double` 런당 | 1 | `ads.goldDouble.perRun` (max 3) | 같은 런에 두 번 2배는 의미가 없다 |
| `sanctum_offering` 하루 | 4 | `ads.sanctumOffering.perDay` (max 20) | §4.1 의 4.4% 계산 |
| **기기 하루 총 노출** | **15** | `ads.dailyImpressionCap` (max 50) | 광고 남용 유저 보호 + eCPM 급락 방지 |
| 로드 타임아웃 | 10s | `ads.loadTimeoutMs` | 스피너가 화면을 잠그지 않게 |
| 표시 타임아웃 | 90s | `ads.showTimeoutMs` | SDK 가 콜백을 영영 안 주는 사고 방어 |

> **"하루"는 기기 로컬 자정 기준**이다(`ads.js` `todayKey()`). UTC 로 하면 한국 유저의 하루가 오전 9시에 끊긴다.
> 카운터는 `bloodsworn.adcap.v1` 에 저장되며 **세이브와 분리**돼 있다 — "데이터 초기화"로 상한을 리셋할 수 없다.

### 4.6 실패 처리 — 유저에게 보이는 문구

`showRewarded()` 의 `reason` 은 UI 문구로 1:1 매핑된다. **에러 코드를 유저에게 보여주지 않는다.**

| reason | 유저에게 | 버튼 상태 |
|---|---|---|
| `capped_run` / `capped_day` / `capped_global` | "오늘은 여기까지다" / "이번 런에는 이미 서약했다" | 애초에 안 그린다 |
| `no_fill` / `unavailable` / `timeout` | "지금은 제물이 닿지 않는다. 잠시 뒤 다시." | 그린다, 눌리면 토스트 |
| `no_consent` | (버튼을 그리지 않는다) | EEA/UK/CH 에서 UMP 가 거부한 상태. §6.1 |
| `dismissed` | (조용히 아무 일 없음) | 보상 없음. **에러 토스트를 띄우지 않는다** |
| `show_failed` / `busy` | "지금은 제물이 닿지 않는다." | 토스트 |
| `entitlement` | (즉시 보상) | 「영원한 서약」 보유자 |

> **`dismissed` 를 실패로 취급해 토스트를 띄우면 안 된다.** 유저가 스스로 닫은 것이고,
> "네가 광고를 끝까지 안 봤다"고 통보하는 것은 짜증만 남긴다.

## 5. 지급 파이프라인 — "결제는 됐는데 못 받았다"를 구조적으로 막는다

이 사고가 나면 **환불 요청과 별점 1점이 동시에** 온다. 소프트런치 규모에서는 평점이 곧 ASO 이고,
`25-GROWTH-AND-UA.md` §2.2 가 평점을 가장 큰 오가닉 레버로 지목했다. 즉 **결제 사고는 UA 사고다.**

### 5.1 2단계 지급 (two-phase grant)

```
구매 성공
   └─► entitlements.pending 에 적재 (디스크에 먼저 쓴다)
          └─► index.drainGrants() 가 게임의 onGrant(grant) 호출
                 └─► 게임이 골드를 실제로 더하고 true 를 반환
                        └─► ackGrant(id) → 원장에서 제거
```

- **`onGrant` 가 `true` 를 반환할 때까지 원장에서 지워지지 않는다.** 예외를 던지거나 `false` 면
  다음 부팅에 다시 흘러나온다. 중복 지급은 `id`(UUID)로 막는다.
- 지급 **전에** ack 하면 그 결제는 영영 증발한다. `onGrant` 구현부에서 이 순서를 반드시 지킬 것.
- `drainGrants()` 호출 시점: **부팅 직후 1회**, **구매 성공 직후**, **복원 직후**.

### 5.2 원장을 세이브와 분리한 이유

| 저장소 | 키 | 지워지는 조건 |
|---|---|---|
| 세이브 | `bloodsworn.save.v1` | 옵션의 "데이터 초기화" |
| **수익화 원장** | `bloodsworn.ent.v1` | **초기화 버튼으로 지워지지 않는다** |
| 광고 상한 | `bloodsworn.adcap.v1` | 지워지지 않는다 |
| 분석 큐 | `bloodsworn.evq.v1` | "분석 데이터 삭제" |

> 초기화 버튼 하나가 결제 이력을 날리는 사고를 **파일 분리로** 막았다.
> 세이브 스키마 마이그레이션(밸런스 패치)이 결제 복구를 깨뜨릴 수 없다는 것도 같은 이유다.

### 5.3 소비성 vs 비소모성

- **비소모성**(`bs_eternal_pact`, `bs_starter`, `bs_skin_ashen`): `owned` 에 기록되고
  `hasEntitlement(key)` 로 동기 조회된다. 이미 소유한 상품은 `visibleSkus()` 가 목록에서 **숨긴다** —
  안 숨기면 중복 구매 시도 → 스토어 에러 → 문의가 온다.
- **소모성**(골드 팩): `owned` 에 남지 않는다. `restorePurchases()` 로 **되살아나지 않는다**(정상).
  ⚠ 그래서 소모성 골드는 **지급 즉시 세이브에 반영**돼야 한다. `onGrant` 안에서 `persistSave()` 를 부른다.

### 5.4 복원 버튼은 필수다

기기 변경·재설치 시 `restorePurchases()` 가 없으면 유저는 산 것을 잃는다.
**Apple 은 비소모성 상품에 대해 복원 경로 제공을 심사에서 요구한다.** 옵션 화면에 반드시 둔다.
복원은 스토어를 정본으로 삼아 **병합(추가)만 하고 삭제하지 않는다** — 오프라인 복원 실패로 권리가 증발하면 안 된다.

## 6. 컴플라이언스가 이 설계에 강제하는 것

> 사실관계와 출처는 전부 `27-COMPLIANCE-AND-SOFTLAUNCH.md` 에 있다. 여기서는 **코드가 무엇을 해야 하는가**만 적는다.

### 6.1 UMP 동의 — 순서를 틀리면 광고가 하나도 안 나간다

```
매 실행: requestConsentInfoUpdate()  →  (REQUIRED 면) showConsentForm()
                                     →  canRequestAds() 확인
                                     →  그 다음에야 광고 로드
```

`ads.js` `initAds()` 는 `ensureConsent()` → `preloadRewarded()` 순서다. **이 순서를 바꾸지 마라.**
`consentAllowsAds()` 가 로드·표시·`isAdReady()` 세 곳 모두를 게이트한다.
`requestConsentInfoUpdate()` 호출 전의 `canRequestAds()` 는 **항상 false** 이기 때문이다.

- 플러그인이 `canRequestAds` 를 노출하면 그 값을 따르고, **노출하지 않으면 true 로 간주**한다.
  (반대로 기본값을 false 로 두면 구버전 플러그인에서 광고가 전부 죽는다.)
- 미준수의 벌칙은 **셧다운이 아니라 매출 손실**(비개인화/제한적 광고로 강등)이다.
- 옵션 화면에 **"광고 동의 다시 설정"**(`resetAdConsent()`)을 둔다 — EEA 동의 철회권.
  EEA 밖에서는 `getConsentState().status === "not_required"` 이므로 버튼을 숨겨도 된다.

### 6.2 개인화 광고를 요청하지 않는다 (`PERSONALIZED_ADS = false`)

- 모든 광고 요청에 `npa: true` 를 붙인다. **iOS 는 ATT 프롬프트를 띄우지 않는다.**
- ⚠ **"추적에 동의하면 보상"은 설계 자체가 불가능하다** — App Review 5.1.2 위반.
  광고 배치 목록(§4)에 그런 항목이 없는 것은 우연이 아니다.
- 대가: eCPM 손실(특히 미국·EU 보상형). 이득: Apple 개인정보 라벨의 "추적에 사용되는 데이터" 분류를
  통째로 회피, ATT 옵트인율 문제 소멸, 심사 리스크 감소. **1인 개발 6개월에서는 이쪽이 남는 장사다.**
- 뒤집을 때 함께 고쳐야 하는 것: `consent.js` / `privacy/` 표 / Play 데이터 안전 양식 / Apple 라벨. **4곳 전부.**

### 6.3 연령 — 18+/16+ 로 선언하고 아동 연령대를 고르지 않는다

- AdMob 의 TFCD/TFUA 는 **deprecated**. 현재 API 는 `setAgeRestrictedTreatment()` 이고,
  비아동 대상이면 **UNSPECIFIED** 로 둔다(= 아무것도 호출하지 않아도 된다).
- ⚠ 대부분의 Capacitor AdMob 래퍼는 아직 구 API 를 노출한다. **구 API 를 호출하지 마라** — 현재 코드는 부르지 않는다.
- ⚠ **스토어 아트가 선언을 덮는다.** 아이콘·피처그래픽이 아동 친화적으로 보이면 Play 가 대상 연령을 바꾸라고 요구한다.

### 6.4 Play Billing 8+ (2026-08-31) — 이 설계의 **최대 미해결 리스크**

`iap.js` 는 어댑터 패턴이라 **결제 SDK 를 이 파일을 고치지 않고 갈아끼울 수 있다**(`registerIapAdapter`).
그렇게 만든 이유가 바로 이 마감이다. 상세와 대안은 `22-BACKEND-AND-REMOTE-CONFIG.md` §5.

## 7. 무엇을 보고 이 설계가 맞았는지 판정하는가

> 기준선 수치(D1/D7/ARPDAU/LTV:CPI)는 **`21-LIVEOPS-AND-ANALYTICS.md` §2 와 `27` §2 가 정본이다.**
> 여기서는 **수익화 고유의 판정 규칙 4개**만 적는다.

| # | 규칙 | 위반 시 조치 |
|---|---|---|
| **M1** | **각성 발동률**(런당 평균)이 광고 도입 전후로 떨어지면 안 된다 | 떨어졌다면 원인 배치를 즉시 끈다. 원격 `ads.*.enabled=false` 로 앱 업데이트 없이 가능 |
| **M2** | `revive` 사용 런의 **평균 최종 인간성**이 미사용 런보다 **낮아야** 한다 | 같거나 높으면 인간성 비용이 실제로 작동하지 않는 것이다 → 비용 상향 |
| **M3** | **결제자와 무과금의 성소 만렙 도달 시점 차이가 "속도"에만 나타나야 한다** | 결제자만 도달 가능한 상태가 생기면 F5 위반. 카탈로그 결함이다 |
| **M4** | ARPDAU 는 **T1 시장(캐나다/네덜란드)에서만 판정한다** | 필리핀 ARPDAU 를 글로벌 신호로 읽는 것이 소프트런치 대표 자책골이다(`27` §2) |

- 이벤트 스키마는 `21` §3.2 가 정본이다. `ad_request` 는 `placement` + `ready`,
  `ad_rewarded` 는 `placement` + `reward_type`, `iap_purchase` 는 `sku` + `price_local` + `currency` + `first_purchase`.
- **런 중 광고 관련 이벤트를 프레임 루프에서 발화하지 않는다.** `track()` 은 초당 20건에서 잘린다.

| H4 | `FE/src/ui/screens/SanctumScreen.jsx` | `sanctum_offering` 버튼 + 상점(IAP) 진입점 | `sanctum_offering`·IAP 불가 |
| H5 | `FE/src/ui/screens/OptionsScreen.jsx` | 구매 복원 / 광고 동의 재설정 / 분석 데이터 삭제 | **Apple 심사 반려**(복원 경로 부재) |
| H6 | `FE/src/state/bridge.js` | `run_start`/`run_end`/`pact_choice`/`awakening` 에 `track()` 부착 + `onRunStart()` | 지표 0건 |

### 8.1 H2 의 설계 제약 — 사망은 **되돌릴 수 있는 상태**여야 한다

현재 사망 경로는 즉시 `RUN_ENDED` 를 emit 한다. 부활을 넣으려면 **사망과 런 종료 사이에 상태가 하나 더** 필요하다.

```
사망 판정 → (부활 가능한가?) ──아니오──► RUN_ENDED (기존과 동일)
                │
               예 (인간성 ≥ 25, 런당 부활 미사용, isAdReady("revive"))
                │
                ▼
          씬 일시정지 + REVIVE_OFFER emit → React 오버레이
                │
     ┌──────────┴──────────┐
   수락(광고 성공)          거절 / 광고 실패 / 8초 무응답
     │                      │
  인간성 −25, HP 50%,     RUN_ENDED
  무적 2초, 씬 재개
```

- ⚠ **8초 타임아웃은 필수다.** React 가 응답하지 않으면(오버레이 렌더 실패 등) 런이 영원히 멈춘다.
  타임아웃은 곧바로 `RUN_ENDED` 로 떨어진다 — **P2 원칙: 광고가 진행을 막지 않는다.**
- ⚠ **각성 「불사의 껍질」 부활과 카운터를 공유한다**(§4.1 전제 2).
