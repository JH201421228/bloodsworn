## 3. 조작 (Input)

### 3.1 레이아웃

```
┌──────────────────────────────────────────────────────────────┐
│ [HP바 ██████░░░░]  Lv.12  [EXP ▓▓▓▓▓░░░░]        05:12  ☠137 │ ← 상단 HUD
│ [인간성 ♥♥♥♡♡]  [각성:2]                                     │
│                                                              │
│                          ⚔                                   │
│                       (플레이어)                              │
│                                                              │
│                                                              │
│   ◉ 조이스틱                                      [⚡대시] ⏸  │ ← 하단
└──────────────────────────────────────────────────────────────┘
```

### 3.2 입력 정의

| 입력 | 동작 | 상세 |
|---|---|---|
| **좌측 화면 절반 터치·드래그** | 이동 | **플로팅 조이스틱**: 처음 닿은 지점이 원점. 최대 반경 48px(논리). 데드존 8px. 아날로그 8방향 이상 연속 |
| **우측 대시 버튼** | 대시 | 이동방향으로 120px 순간이동, **무적 0.25초**, 쿨다운 3.0초. 정지 중이면 바라보는 방향 |
| **일시정지 버튼** | 정지 | 우상단. 게임 정지 + 옵션 |
| **레벨업 중** | 카드 탭 | 게임 완전 정지(`scene.pause`). 카드 3장 중 1개 탭. 리롤 버튼 별도 |
| 공격 | **전자동** | 플레이어 입력 없음 |
| 키보드 (개발용) | WASD/방향키 + Space(대시) | **개발 중 PC 브라우저 확인 전용.** 출시 대상은 Android·iOS 터치뿐이며, 키보드 조작을 전제한 설계는 하지 않는다 |

### 3.3 조작 원칙
- **한 손으로도 플레이 가능해야 한다.** 대시는 있으면 좋은 것이지 필수가 아니어야 한다.
- 조이스틱은 **손가락이 화면을 가리지 않도록** 좌하단 영역에 고정 배치, 반투명 30%.
- 대시 버튼 히트박스는 시각 크기의 **1.5배** (모바일 오조작 방지).

### 4.2 스탯 계산 순서 (중요)

```
최종값 = (기본값 + Σ가산) × Π곱연산 × (각성 보정)
```
가산 → 곱연산 → 각성 순서를 **반드시 고정**한다. 순서가 바뀌면 밸런스가 무너진다.
자세한 구현은 `06-TECH-DESIGN.md` §StatSystem.

## 5. 경험치 & 레벨

### 5.1 필요 경험치 곡선

```
requiredExp(level) = floor(5 + level * 4 + level^1.55)
```

**공식이 진실이다. 아래 표는 공식을 대입한 검산값이다.**

| Lv | 필요 EXP | 누적 |
|---|---|---|
| 1→2 | 10 | 10 |
| 2→3 | 15 | 25 |
| 5→6 | 37 | 127 |
| 10→11 | 80 | 561 |
| 15→16 | 131 | 1,096 |
| 20→21 | 201 | 1,935 |

목표: **6분 런에서 Lv 18~22 도달** (§1 참조).
→ 검산 결과 **Lv20~21 도달**(총 EXP 1,799, 레벨업 19~20회)로 목표 충족. `05-COMBAT-AND-BALANCE.md` §7

### 5.2 경험치 오브
- 적 처치 시 100% 드롭. 3티어: 청록(1) / 파랑(5) / 보라(20)
- **자석 반경 내 진입 시 플레이어를 향해 가속 이동**(초기 60px/s → 최대 400px/s)
- **런 시작 시 EXP 오브 6개를 플레이어 주변에 선배치**(`waves.json` S1 `preplacedOrbs`).
  순수 킬 EXP만으로는 첫 레벨업이 약 17초 — §1의 "15초 이내" 목표를 못 맞춘다. 선배치로 약 11초.
- **오브 합체 최적화:** 화면 내 오브 200개 초과 시 가장 오래된 오브들을 자동 병합 (성능 필수)

## 9. 메타 진행 — 성소(Sanctum)

런 종료 시 **골드** 획득: `골드 = 처치수 × 1 + 생존초 × 0.5 + 보스처치 × 200 + 엘리트 보너스`

> ⚠️ **이중 계산 금지:** 일반 적의 `gold` 필드는 **0**으로 둔다(위 식의 `처치수 × 1`이 이미 반영).
> 엘리트만 개별 보너스를 갖는다 — EL1 = 25, EL2 = 50.
> 검산 기준 **클리어 1회당 약 1,318골드**, 성소 만렙(10,930골드)까지 **9~11회 클리어**.

## 10. 게임 상태 머신 (Scene 구성)

| Scene | 역할 | React/Phaser |
|---|---|---|
| `BootScene` | 설정 로드, 로딩바 준비 | Phaser |
| `PreloadScene` | 전 에셋 로드, 아틀라스 파싱, 애니메이션 등록 | Phaser |
| `GameScene` | 실제 런. 월드/적/무기/충돌 | Phaser |
| `HudScene` | HP/EXP/타이머 (Phaser 오버레이, 60fps 갱신) | Phaser |
| **React 레이어** | 타이틀 / 성소 / **PACT 카드** / 결과 / 옵션 | React + Zustand |

> **핵심 설계:** 실시간 전투 = Phaser, **정지 상태 UI = React**.
> PACT 카드는 게임을 `pause`시키므로 React로 그리는 것이 압도적으로 빠르다.
> 브릿지 규약은 `06-TECH-DESIGN.md` §EventBus.

## 11. 난이도 곡선 (6분)

| 시간 | 적 HP 배율 | 적 공격력 배율 | 스폰 간격 | 동시 적 수 |
|---|---|---|---|---|
| 0:00 | 1.0 | 1.0 | 1.20s | ~15 |
| 1:30 | 1.6 | 1.2 | 0.75s | ~40 |
| 3:00 | 2.8 | 1.5 | 0.45s | ~80 |
| 4:30 | 4.5 | 1.9 | 0.28s | ~130 |
| 6:00 | — | — | 스폰 중단 | 0 (보스전) |

배율 공식: **`hpMult(t) = 1.0 + (t/60)^1.55 × 0.33`** (t = 경과 초)

> 🔧 **정정(검산 반영):** 초안의 계수 0.55는 위 표와 불일치했다(t=270s에서 6.66 vs 표 4.5).
> **0.33**이 표의 4개 앵커(1.0 / 1.6 / 2.8 / 4.5)와 ±0.1 내로 일치한다. 상세: `05-COMBAT-AND-BALANCE.md`
