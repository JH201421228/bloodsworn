## 0. 이 문서가 푸는 문제

**무기는 레벨 5에서 끝난다.** `weapons.json` 의 모든 무기가 `maxLevel: 5` 이고,
만렙이 되면 `PactSystem.candidates()`(`PactSystem.js:60`)가 그 축복을 후보에서 뺀다.
저장소 전체에 evolve / evolution / 진화 개념이 **하나도 없다.**

그 결과 런의 후반부는 이렇게 된다.

```
레벨  1 ~ 12   무기를 고르고 키운다        <- 선택이 있다
레벨 13 ~ 20   무기가 만렙이 된다
레벨 21 이상   남은 것은 체력·이동속도뿐   <- 선택이 사라진다
```

**후반 레벨업이 "숫자가 조금 오른다"로 수렴한다.** 이것이 `30` 이 진단한 "평면적"의
나머지 절반이다. 조우가 전투 화면의 공백을 채운다면, 룬은 **성장 곡선의 공백**을 채운다.

**이 문서가 다루지 않는 것**
- 룬을 어디서 얻는가 → `30-ENCOUNTERS-AND-FIELD-EVENTS` §3
- 축복·대가의 수치 → `04-PACT-SYSTEM`
- 각성 → `04-PACT-SYSTEM` §7. 룬은 각성과 별개의 축이다 (§1.3)

## 1. 룬이란 무엇인가

### 1.1 한 줄 정의

> **룬은 무기에 새기는 것이고, 무기의 「수치」가 아니라 「거동」을 바꾼다.**

축복은 damage +18% 를 준다. 룬은 **"화염탄이 명중하면 근처 적으로 튄다"**를 준다.
전자는 더하기이고 후자는 다른 게임이다.

### 1.2 세 축의 분업 ★ 이 문서에서 가장 중요한 절

이 게임에는 이제 성장 축이 셋이다. 셋이 겹치면 무엇을 고르든 같아진다.

| 축 | 무엇을 바꾸나 | 언제 | 어디서 | 대가 |
|---|---|---|---|---|
| **축복 (PACT)** | 수치 | 레벨업마다 | 카드 3택 | 대가가 붙는다 |
| **룬** | 무기의 거동 | 조우에서만 | 좌판 3택 | 마녀에게 살 때만 |
| **각성** | 대가를 뒤집는다 | 태그 3중첩 | 자동 | 없음(대가가 보상이 된다) |

> **룬은 레벨업 카드에서 절대 나오지 않는다.**
> 이것이 룬과 축복을 가르는 유일하고 가장 중요한 선이다. 카드에 룬을 섞으면
> PACT 는 "가끔 좋은 게 나오는 뽑기"가 되고, 조우는 존재 이유를 잃는다.
> **룬을 조우 전용으로 묶어야 조우가 "가야 할 이유"를 갖는다.** 두 시스템은 서로를 지탱한다.

### 1.3 각성과 겹치지 않는 이유

각성은 **대가**를 뒤집는다(`AwakeningSystem.js`, `awakenings.json`). 룬은 **무기**를 바꾼다.
겹치는 지점이 없다. 다만 마녀의 룬에 대가가 붙으므로 **룬 구매가 각성을 앞당길 수 있다** —
이것은 의도된 상호작용이며, 룬 트리와 각성을 동시에 노리는 빌드가 성립한다.

## 2. 구조 — 무기당 3단계, 각 단계 2택

```
        무기 (W1 ~ W4)
             |
      T1 ---+--- 2택 중 1          거동 변형   (무기 Lv3 이상)
             |
      T2 ---+--- 2택 중 1          거동 변형   (무기 Lv5 · T1 보유)
             |
      T3 ---+--- 2택 중 1          ★ 진화      (T2 보유)
```

- 무기 1개당 룬 슬롯 **3칸** (T1/T2/T3 각 1칸). 한 번 새기면 바꿀 수 없다
- 무기 4종 x 6룬 = **총 24룬**
- 한 무기의 최종 조합은 2 x 2 x 2 = **8가지**. 무기 4개면 조합 공간은 8^4

### 2.1 왜 「단계마다 2택」인가

3택 이상으로 하면 좌판이 3개 x 무기 여러 개가 되어 화면에 다 못 놓는다.
`30` §1.3 의 「선택을 공간으로 바꾼다」가 물리적으로 무너진다.

2택이면 마녀의 좌판 3개에 **서로 다른 무기의 룬**을 하나씩 올릴 수 있다.
즉 플레이어가 고르는 것은 "어떤 룬"이 아니라 **"어떤 무기를 키울 것인가"** 가 된다.
이쪽이 훨씬 큰 선택이다.

### 2.2 왜 T3 만 「진화」인가

T1/T2 까지도 규칙을 바꾸면 무기가 매번 딴것이 되어 손에 익지 않는다.
T1/T2 는 **같은 무기를 다르게 쓰는 법**이고, T3 는 **다른 무기가 되는 것**이다.
T3 는 무기 만렙 + T1 + T2 를 요구하므로 한 런에서 보통 1~2개만 본다. 그래서 사건이 된다.

## 4. 게이트 — 언제 제시되는가

룬이 좌판에 오르려면 **네 조건을 전부** 만족해야 한다.

| # | 조건 | 왜 |
|---|---|---|
| G-1 | 그 무기를 **보유**하고 있다 | 안 쓰는 무기의 룬은 쓰레기다 |
| G-2 | 무기 레벨 요건 — T1: Lv3+ / T2: Lv5 / T3: Lv5 | 룬은 **만렙 이후의 성장**이라는 역할을 지킨다 |
| G-3 | 선행 단계를 **이미 새겼다** — T2 는 T1 필요, T3 는 T2 필요 | 트리가 트리이려면 순서가 있어야 한다 |
| G-4 | 그 단계 슬롯이 **비어 있다** | 한 무기의 T1 은 하나뿐이다 |

⚠ **G-2 가 T1 을 Lv3 으로 잡은 이유**: Lv5(만렙)로 하면 첫 룬이 런의 중반 이후에나 나온다.
`30` §4.1 의 창 W2(약 168초)에서 마녀가 줄 게 없어 재추첨만 반복된다. Lv3 이면 W2 에 닿는다.

**제시할 룬이 하나도 없으면 마녀는 등장하지 않는다** (`30` §4.2 규칙 3).

## 5. 구현 — 후크 5개

### 5.1 ★ 가장 먼저 알아야 할 함정

```js
// CombatSystem.js:233
w.s = def.levels[lv - 1];    // <- JSON 객체를 그대로 참조한다
```

**`w.s` 는 `weapons.json` 에서 import 한 객체 그 자체다.** 룬이 여기에 값을 쓰면
**JSON 원본이 오염되고 다음 런까지 남는다.** (`SpawnSystem.applyTuning`, `SpawnSystem.js:76` 이
같은 함정을 이미 겪었다.)

→ 룬은 `w.s` 를 **절대 수정하지 않는다.** 무기 인스턴스에 별도 필드를 둔다.

```js
// addWeapon() 에서 초기화
w.runes = { t1: null, t2: null, t3: null };
w.mods  = { arcMul: 1, radiusMul: 1, countAdd: 0, pierceAdd: 0, cdMul: 1, ... };
// 룬을 새길 때마다 mods 를 처음부터 다시 계산한다 (누적 곱 오차 방지)
```

발사 지점에서는 `w.s.x * w.mods.xMul` 로 읽는다. `w.s` 는 읽기 전용으로 유지된다.

### 5.2 후크 목록

```js
// (1) 무기 인스턴스 — 룬 슬롯과 mods 초기화
CombatSystem.addWeapon(id, level = 1)                CombatSystem.js:223

// (2) 발사 루프 — cdMul / countAdd 적용
CombatSystem.fireWeapons(dt)                         CombatSystem.js:238

// (3) 온-히트 — 모든 피해가 반드시 통과한다. 흡혈·연쇄·작렬의 훅
CombatSystem.queueDamage(enemy, amount, knockback, src = null)   CombatSystem.js:373
CombatSystem.flushDamage()                           CombatSystem.js:378  (치명타·사망 판정)

// (4) 투사체 per-shot 오버라이드 — 관통·유도·연쇄
ProjectileSystem.fire(def, x, y, angle, opts)        ProjectileSystem.js:157
    opts = { damage?, knockback?, speed?, range?, pierce?, scale?, life?, gen?, exclude? }
ProjectileSystem.onHit(p, e)                         ProjectileSystem.js:324

// (5) 전역 스탯 — src 접두 "rune:" 로 그룹 해제 가능하게
StatSystem.add(stat, op, value, "rune:" + runeId)    StatSystem.js:63
StatSystem.removeBySrc("rune:" + runeId)             StatSystem.js:70
```

★ **`src` 접두 규약**: `bls:` / `toll:` / `item:` / `sanctum:` / `stage:gimmick` 이 이미 있다.
룬은 `rune:` 을 쓴다.

### 5.3 데이터 스키마 — `awakenings.json` 을 승계한다

`awakenings.json` 의 `effects[].op:"special" + id + params` 패턴이 **"수치가 아니라 규칙을
바꾸는 것"을 이미 데이터로 표현하고 있다.** 새 문법을 발명하지 않는다.

```jsonc
// runes.json
{
  "id": "rn_w2_chain",
  "weapon": "W2",
  "tier": 3,
  "name": "연쇄 화염",
  "glyph": "◈",                      // 아트가 오기 전 폴백 (awakenings.json 의 sigil 과 같은 방식)
  "icon": null,                      // Codex 아이콘이 오면 프레임 키가 들어간다
  "desc": "적중하면 근처 적에게 3회 튄다",
  "requires": { "weaponLevel": 5, "tier": 2 },
  "effects": [
    { "op": "special", "id": "chain_bounce", "params": { "count": 3, "falloff": 0.25, "range": 70 } }
  ]
}
```

- `op: "mod"` — `w.mods` 를 바꾸는 단순형 (T1 대부분)
- `op: "stat"` — `StatSystem.add` 로 흘리는 전역형
- `op: "special"` — `RuneSystem` 안의 전용 핸들러. T2/T3 대부분

`op: "special"` 의 `id` 마다 `RuneSystem` 에 핸들러 함수가 하나씩 있다.
`AwakeningSystem.js`(838줄)가 같은 구조의 선례다.

### 5.4 성능 제약 ★

**T3 진화 6종이 전부 투사체를 늘린다.** 유성우 +3발, 연쇄 3회, 뼈 사출, 참격 파동.
`ProjectileSystem` 풀 상한은 **160**(`ProjectileSystem.js:38`)이다.

- 룬 효과는 **절대 `new` 를 부르지 않는다.** 기존 풀을 쓴다
- 풀이 가득 차면 조용히 발사를 건너뛴다 (이미 그렇게 동작한다)
- 연쇄는 `gen` 필드로 세대를 세고 **1세대까지만 튄다**. `BossSystem` 의 분열탄이 같은 규칙을 쓴다
  (`BossSystem.js:911`) — 무한 분열은 가장 좁은 화면을 몇 초 만에 채운다
- ⚠ **1% Low >= 40fps** 가 차단선이다(`13-QA` §6). T3 룬 2개 + 적 150체에서 반드시 측정할 것

## 6. UI — 새 화면을 만들지 않는다

### 6.1 획득 — 좌판 (`30` §1.3)

룬을 고르는 화면은 **없다.** 마녀·필드보스·궤가 좌판에 올려 두면 밟는다.
게임은 멈추지 않는다.

### 6.2 조망 — 일시정지 화면

`UiLayer.jsx` 의 `PauseOverlay` 는 주석에 이렇게 적혀 있다:
> *"이 게임에서 빌드 전체를 조망하는 유일한 화면이다. 별도 인벤토리 화면을 만들지 않는다."*

**그 규약을 그대로 따른다.** 룬 트리는 일시정지 화면 안에 들어간다.
보유 무기별로 한 줄, 새긴 룬은 글리프, 빈 칸은 점선.

```
W1 피의 송곳니   Lv5   [벌어진 아가리] - [피 빨기] - [ ? ]
W2 화염탄        Lv5   [쌍포]         - [작렬]    - [연쇄 화염]
W3 뼈 회오리     Lv3   [ . ]          - [ . ]     - [ . ]
```

> **거부한 설계 — 「전용 룬 트리 화면」**
> 노드와 선을 그린 진짜 트리 UI. 가로 640x360 에서 4무기 x 7노드를 그리면
> 노드 하나가 20px 남짓이 되어 모바일에서 읽을 수 없다. 그리고 화면이 하나 더 늘면
> `10-UIUX-LANDSCAPE` §10.4 의 화면 상태 머신을 고쳐야 한다.
> **트리의 모양은 좌판이 이미 보여준다** — 지금 고를 수 있는 2개가 곧 그 시점의 트리다.
