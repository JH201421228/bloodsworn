> 로컬 Xcode를 전제한 절차는 이 프로젝트에 존재하지 않는다. 절차 전문: `14-BUILD-AND-DEPLOY.md` §5.5 · §7.5

- [ ] **D0-15** `P0` **Apple Developer Portal에 App ID `com.bloodsworn.game` 등록 + Play Console 패키지명 선점** (15m)
      둘 다 무료·선착순·영구다. **밑줄이 없어야 한다** — Android는 허용하지만 **Apple은 거부**한다.
      ⚠ 스캐폴드 기본값 `com.superdimension.app`으로 "테스트 삼아" 첫 업로드를 하면 **그 값이 영구 고정**되고,
      옛 ID는 **재사용 불가**이며 평점·리뷰·업데이트 경로를 전부 잃는다. Capacitor는 `appId` 하나로
      iOS `PRODUCT_BUNDLE_IDENTIFIER`와 Android `applicationId`를 함께 seed하므로 **반드시 일치시킨다**
- [ ] **D0-16** `P0` **App Store Connect 앱 레코드 생성** (Platforms / App Name / Primary Language / **Bundle ID** / SKU / User Access)
      **+ 연령 등급 설문 응답** (30m). 앱 레코드는 **빌드 업로드보다 먼저** 존재해야 한다.
      등급 = **13+** (2025년 개편 체계 4+/9+/13+/16+/18+. 12+·17+는 폐지). 근거 — 9+는 "가끔의" 판타지 폭력,
      13+는 "**빈번한**" 판타지 폭력이고 서바이버즈는 정의상 빈번하다. 서술자 응답: `Cartoon or Fantasy Violence` = **Frequent** /
      `Realistic Violence` = None / `Loot Boxes` = **None** / 광고·UGC·웹접근 = 전부 None.
      **축소 신고 금지**(양 스토어 삭제·정지 사유). 등급은 **올릴 수는 있어도 내릴 수 없다**.
      ⚠ 2026-01-31 이후 등급 미응답 시 "제출 시 중단"이 발생하는데 **그 중단이 TestFlight 업로드에도 걸리는지 확인되지 않았다**
      (⚠ 확인 필요(2026-08-10 기준 미확인)) → **10분 들여 그냥 채운다.** 이번 조사에서 나온 가장 큰 일정 리스크다
- [ ] **D0-17** `P0` 🚨 **iOS 서명 자산 4종 확보 — Mac 없이 `openssl`만으로** (60m)
      ① `openssl genrsa` → 개인키, `openssl req` → **CSR** ② 포털에 CSR 업로드 → 배포 인증서(`.cer`) → `openssl x509`로 `.pem` →
      `openssl pkcs12 -export`로 **`.p12`(암호 필수)** ③ App Store 배포용 **프로비저닝 프로파일**(`.mobileprovision`)
      ④ **App Store Connect API 키**(`.p8` + Issuer ID + Key ID) — CI 비대화식 인증에서 **2FA를 우회할 수 있는 유일한 방법**
      🔒 **`.key` `.p12` `.p8` `.mobileprovision`은 절대 커밋 금지.** Android keystore(D0-2)와 **완전히 같은 강도**로 취급한다
- [ ] **D0-18** `P0` **Codemagic 계정 생성 + GitHub 저장소 연결 + 시크릿 4종 등록** (15m)
      무료 **500 macOS M2 분/월 ≈ 50회 빌드**. GitHub Actions 개인 Free는 **macOS가 10배 배수**라 실질 약 200분 ≈ 20회뿐이고,
      Xcode Cloud는 **Xcode에서 설정해야 하므로 Mac이 없는 이 프로젝트에서는 탈락**이다.
      근거 — 로컬 재현이 불가능해 **CI 로그가 유일한 진단 수단**이므로 **시행착오 횟수가 곧 성공 확률**이다.
      ⚠ 확인 필요(2026-08-10 기준 미확인) — GitHub Actions 무료 분수는 3자 출처. 채택을 뒤집을 때 공식 청구 문서로 재확인

- [ ] **T552** `P1` 🍎 **`@capacitor/preferences` write-through** (약 30줄 · 플러그인 1개 추가) — **iOS 때문에 기존 결정을 뒤집는다**
      Capacitor 공식 문서는 `localStorage`를 **transient**로 규정하고 "데이터가 결국 소실될 것을 앱이 전제해야 한다"고 쓴다.
      **저장공간이 부족하면 OS가 WebView의 로컬 저장소를 회수**하며 IndexedDB도 iOS에서 같은 위험이 있다.
      `@capacitor/preferences`는 iOS `UserDefaults` / Android `SharedPreferences`를 쓰고, **`UserDefaults`는 WebKit 저장소 회수 대상이 아니다.**
      ```
      부팅 : Preferences에서 읽는다 → 없으면 localStorage에서 읽어 마이그레이션
      저장 : localStorage에 동기 기록(핫 캐시) + Preferences에 write-through(비동기)
      ```
      **전면 교체가 아니라 write-through인 이유:** Preferences API는 **비동기**라 동기 `localStorage`의 드롭인 대체가 아니다.
      게임 루프 중 저장 지점을 전부 async로 바꾸는 건 7일 스코프에서 위험하다. 수 KB JSON 세이브는 Preferences 적정 범위다.

      ⚠ **`iosScheme`/`server.hostname`을 나중에 바꾸면 origin이 바뀌어 기존 세이브가 전량 고아가 된다.** Day 1에 정하고 건드리지 않는다
