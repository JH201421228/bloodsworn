## 1. 이번 세션에 들어간 것 (커밋 5개)

### `b92049d` 「화면 흔들림 OFF」를 우회하던 9곳

`cam.shake` 직접 호출 9군데가 접근성 옵션 게이트를 지나치고 있었다. 전부 `FxSystem.shake(kind)` 로 보냈다.

- `rockfall` 은 표에 키가 없어 **영구 무효**였다. 같은 일이 또 생기면 즉시 드러나게,
  표에 없는 키는 **게이트보다 먼저** 경고한다(게이트 뒤에 두면 "흔들림 OFF" 로 검증할 때 영영 안 드러난다).

### `0249396` 예외로 죽으면 흰 화면만 남던 것

`FATAL_ERROR` 는 **구독만 있고 쏘는 쪽이 0건**이었다. 세 갈래(window / React / Phaser)를 이었다.

- **★ 오류 화면은 React 가 아니라 `index.html` 의 정적 DOM 이다.**
  이 화면이 필요한 순간은 정의상 React 트리가 죽은 순간이고, 흰 화면의 대표 원인은 예외가 아니라
  **번들이 아예 안 뜨는 것**(청크 404·문법 에러)이다. `dist/assets/index-*.js` 를 지우고 띄워 실증했다.
  스타일도 인라인이다 — `index.css` 는 `main.jsx` 가 import 하므로 번들이 죽으면 스타일도 죽는다.
- Phaser 함정 둘: rAF 는 **다음 프레임 예약이 콜백 뒤에** 있어 씬이 한 번만 던져도 게임이 영원히 언다.
  `loop.callback` 을 덮어쓰는 방식은 `READY` 가 `Game.start()` 보다 먼저 와서 **그물이 조용히 걷힌다**(접근자로 교체).
  멈춘 씬을 `resume()` 후 `stop()` 하면 **죽인 씬이 되살아난다**(`resume` 은 큐잉, `stop` 은 즉시).
- 저장 잠금을 **화면보다 먼저** 건다. 깨진 상태를 디스크로 내보내면 다음 실행도 같은 자리에서 죽는다.

## 3. 함정 — 여기서 시간을 버린다

### 빌드

- **JDK 21 이 필요하다. 17 이 아니다.** 두 오류 메시지는 **반대 방향**을 가리킨다:
  `invalid source release: 21` = JDK 가 **낮다** / `Unsupported class file major version` = **높다**.
  이제 `tools/gradle.mjs` 가 알아서 찾으므로 `JAVA_HOME` 을 안 잡아도 된다.
- **APK 용량을 잴 때는 `clean` 을 붙여라.** zipflinger 가 지운 항목을 패딩으로 남겨 크기가 안 줄어든 것처럼 보인다.
- 경로에 한글이 있어 `android.overridePathCheck=true` 가 필요하다.

### ★ 검증할 때 파이프로 종료 코드를 가리지 마라

이번 세션에 **두 번** 걸렸다. `node tools/gradle.mjs … | tail -6` 은 **`tail` 의 종료 코드**를 돌려준다.
빌드가 실패했는데 exit 0 으로 보여서, 하마터면 **몇 시간 전의 옛 APK 를 최종본으로 넘길 뻔했다.**

```bash
# 이렇게
node tools/gradle.mjs clean assembleDebug > build.log 2>&1; echo "EXIT=$?"; grep BUILD build.log
```

APK 가 정말 새것인지는 **타임스탬프와 내용물**로 확인하라:
```bash
unzip -l app-debug.apk | grep -c 'assets/generated/'   # 0 이어야 한다
```

### 브라우저 검증

- Chrome 은 반드시 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding
  --disable-background-timer-throttling` 로 띄운다. **가려진 창은 rAF 가 얼어 씬 전환이 안 된다.**
- 다 쓴 크롬은 **디버그 포트와 `user-data-dir` 양쪽으로** 쓸어라. 부모를 죽여도 자식이 남는다.

### 에뮬레이터 렌더 깨짐 — **재조사하지 마라**

「출정지」 화면이 **5회 중 1회** 깨져 보인다(카드가 비고 대각선 잔글씨 띠와 삼각형 쐐기).
**앱 코드 문제가 아님을 확정했다.** 전체 근거는 커밋 `ed132cd` 본문에 있고, 요지는:

- 쐐기가 **다른 카드의 글자 위**를 덮었다 — CSS 페인트 순서상 **일어날 수 없다**
- 경계가 **기울기 0.25 의 직선**이고 요소 경계를 가로지른다 = 화면 좌표 단위 손상
- 같은 번들을 브라우저에서 2340x1080 · DPR 2.75 로 재현 시도 → 전부 정상, DOM 좌표는 픽셀 일치
- 깨진 스크린샷 두 장의 md5 가 같다 = 그 사이 **프레임 갱신이 없었다**

⚠ 「해금/잠김 CSS 분기가 원인」이라는 가설은 **틀렸다.** stage1 만 해금이라 그 분기가 성립하지 않는다.
**고쳐야 할 근거는 실기기 재현 하나뿐이다.**
