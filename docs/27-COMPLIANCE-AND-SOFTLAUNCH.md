## 1. 소프트런치 국가 선정

funnel 지표는 시장을 건너 이동하지만 **수익화 지표는 이동하지 않는다.** 그래서 두 시장을 병행한다.

| 티어 | 국가 | Android CPI(추정) | 무엇을 읽는가 |
|---|---|---|---|
| T1 리텐션 검증 | 캐나다 / 호주 / 뉴질랜드 | $1.00~2.50 | 미국과 가장 유사한 행동. 온보딩·리텐션·세션·크래시 |
| T2 T1급 지출 저비용 | 네덜란드 / 북유럽 / 프랑스 / 독일 | $0.60~1.50 | 하이브리드 캐주얼에 적합. 단 GDPR/CMP 부담을 첫날부터 떠안는다 |
| T3 광고 내성 | 필리핀 / 인도네시아 / 베트남 | $0.20~0.60 | 보상형 광고 시청률·노출/DAU. **절대 ARPDAU 판단 불가** |
| T4 결제·메타 | 폴란드 / 튀르키예 / 브라질 | $0.15~0.60 | 결제 통합 깊이. 리텐션 데이터는 서구권 판단에 오해 유발 |

**첫 소프트런치에서 피할 곳:** 미국·일본·한국·중국 — 배우기엔 너무 비싸다.

**본 프로젝트 권고: 필리핀 + 캐나다** (또는 필리핀 + 네덜란드).
필리핀에서 싼 설치로 코어 루프와 보상형 광고 반응을 읽고, T1 시장에서 리텐션·ARPDAU 를 신뢰한다.
**1차에서 EEA 를 일부러 뺀다** — CMP/GDPR 부담을 뒤로 미룰 수 있다(1인 개발에 실질적 이득).
⚠ 단 **브라질·인도네시아는 2026-09-30 개발자 인증 시행 대상**이다. 그 시기에 넣으려면 등록을 먼저 끝내야 한다.

신뢰도: MEDIUM (실무자 블로그. CPI 수치는 단일 출처이므로 자릿수 수준으로만 신뢰할 것)

## 2. 글로벌 출시 게이트 — 숫자로

### 리텐션
| 지표 | 중단·수정 | 반복 개선 | 글로벌 진행 |
|---|---|---|---|
| D1 | 25% 미만 | 25%~상승 중 | **28~32% 이상** |
| D7 | 8% 미만 | 8% 내외 상승 | 8% 이상(상위 1/4) |
| D30 | 3% 미만 | 곡선 개선 중 | 안정적 |
| CPI (지출 3배 시) | +50% 상승 | 30~50% | 30% 미만 |

★ **현실 보정이 중요하다.** 일부 실무 문서는 "D1 40%"를 목표로 제시하지만,
GameAnalytics 2025 실측 벤치마크의 **전체 중앙값 D1 은 약 22%**, 상위 1/4 이 26.5~27.7% 이고
**D7 중앙값은 3.4~3.9%** 다. iOS D1 31~33% vs Android 25~27%.
→ **Android 기준 D1 28~32% 로 게이트를 잡는다. 40% 는 상위 10% 수치이지 중앙값이 아니다.**

### 수익화
- ARPDAU: 광고 전용 캐주얼 $0.01~0.05 / **하이브리드 캐주얼 $0.15~0.50**
- 결제 전환 D30 기준 2%+, LTV:CPI **1.5배 이상**(D30)
- D30 ROAS 참고치(캐주얼): Android 약 15% / iOS 약 47% → **Android 회수는 수개월짜리다**
- 보상형 eCPM (캐주얼 Android, 2025 H1): EU/NA $8.90 · JP/KR $6.87 · SEA $1.64 · 인도 $0.10
- 기술 게이트: 크래시율 0.5% 미만

★ **가장 중요한 구조적 통찰:** 리텐션·세션 길이·크래시율·완주율은 **모든 시장에서 신뢰**한다.
ARPDAU 와 결제 전환은 **글로벌 소비자 프로필과 유사한 시장에서만** 신뢰한다.
필리핀 ARPDAU 를 글로벌 신호로 읽는 것이 소프트런치의 대표적 자책골이다.

### 예산 — 알고리즘이 정하는 하한이 있다
- 플랫폼 학습이 작동하려면 **광고 세트당 하루 $300~500**
- D1 을 읽으려면 **코호트당 유료 설치 약 900~1,000건**
- 인디 최소 실행: 1개 시장 4주, **총 $11,000~23,000**
→ **월 $9k 를 한 시장에 못 쓴다면 유료 UA 대신 오가닉/크리에이터 검증으로 가고,
유료 UA 는 마지막 확장 테스트에만 쓴다.** 그 아래는 노이즈를 사는 것이다.

## 3. Play 배포 메커니즘

- **국가 제한**: Play Console → 트랙 → Countries/regions. 테스트 트랙은 기본적으로 프로덕션과 동기화되며 해제 가능.
- **테스트 트랙**: 내부(100명, 국가 무관, 스토어 비노출) / 폐쇄(리스트당 2,000명, **프로덕션과 같은 국가 제한**) / 공개(스토어 검색 노출).
- **소프트런치에는 공개 테스트가 아니라 "국가를 제한한 프로덕션"을 쓴다.** 깨끗한 스토어 등록정보, 실제 IAP, 실제 광고 fill, 정상 ASO 가 필요하다.
- **단계적 출시(staged rollout)**: 비율 기반이고 **지역이 아니라 무작위**로 대상이 정해진다. 자동 증가하지 않는다(수동).
  ⚠ **시작한 뒤에는 국가를 뺄 수 없다. 추가만 가능하다.** → 국가 목록을 시작 전에 확정할 것.
- **관리형 게시(managed publishing)** 권장. 단 내부 테스트 트랙은 적용되지 않는다.
- ⚠ **일방통행:** "무료로 제공된 앱은 유료로 바꿀 수 없다." 바꾸려면 새 패키지명으로 새 앱을 만들어야 한다.
  **무료 + IAP 는 해당 없음 — 우리 모델은 안전하다.**
- 가격 템플릿은 2025-10-27 부로 다중 상품 관리 기능이 중단됐다.

## 4. 아동 대상 / COPPA — 18+ 로 선언한다

**Families 정책을 피하려면 아동 연령대를 하나도 선택하지 않는다.** 그러면
Families 인증 광고 SDK 제한, 중립적 연령 화면, 아동 데이터 전송 금지에서 자유롭다.

### 함정 3가지
1. **스토어 등록정보의 인상이 선언을 덮는다.** 마케팅 자산이 아동 친화적으로 보이면
   Play 가 **그래픽을 바꾸거나 대상 연령 선언을 바꾸라고 요구**한다.
   → 아이콘·피처그래픽·스크린샷을 성인 코드(어두운 팔레트, 전투 프레이밍)로 유지할 것.
   BLOODSWORN 의 혈맹 테마는 유리하지만 **심사 대상은 스토어 아트**다.
2. **아동 연령대를 하나라도 고르면 전부 적용된다** — Families 인증 SDK만 사용 + 중립 연령 화면.
3. **"연령 미상 사용자"도 아동으로 취급된다.** 13+ 로 선언하고 연령 게이트를 두지 않으면 애매한 지대다.
   → **가장 깨끗한 자세: 16+/18+ 만 선언, 아동 연령대 없음, 연령 게이트 불필요.**

### AdMob 쪽
`tagForChildDirectedTreatment`(TFCD) / `tagForUnderAgeOfConsent`(TFUA) 는 **둘 다 deprecated** 이고
현재 API 는 **`setAgeRestrictedTreatment()`** (CHILD / TEEN / UNSPECIFIED) 다.
⚠ 대부분의 튜토리얼과 Capacitor AdMob 플러그인 래퍼는 아직 구 API 를 노출한다. 비아동 대상이면 UNSPECIFIED 로 두면 된다.

## 5. 데이터 안전 양식 — 서드파티 SDK 것도 우리가 신고한다

Play 데이터 안전 양식은 **우리 코드가 아니라 앱이 수집하는 전부**를 신고한다. Google 이 신고할 내용을 공개한다.

**Google Mobile Ads SDK** ([공식 공개](https://developers.google.com/admob/android/play-data-disclosure))
수집·공유: **IP 주소**(대략적 위치) / **사용자 상호작용**(실행·탭·동영상 시청) / **진단**(실행 시간·행 비율·전력) /
**기기·계정 식별자**(광고 ID, 앱 세트 ID, 로그인 계정 ID). 목적: **광고·분석·부정행위 방지**. 전송 중 TLS 암호화.

**Firebase** ([공식 공개](https://firebase.google.com/docs/android/play-data-disclosure))
Analytics 는 사용 데이터, Crashlytics 는 스택 추적·크래시 시점 앱 상태·기기 메타데이터 + 우리가 추가한 커스텀 로그/사용자 ID.
HTTPS 전송. 최종 사용자 데이터 삭제를 지원하므로 **삭제 요청 항목에 "예"로 답할 수 있다.**

**실무 매핑:**
`기기 또는 기타 ID`(수집+공유, 광고/분석/부정방지) · `앱 활동 → 앱 상호작용`(수집, 분석+광고) ·
`앱 정보 및 성능 → 크래시 로그 + 진단`(수집, 분석) · IP 기반 지역 추정을 켜두면 `대략적 위치`.
**전송 중 암호화: 예 / 삭제 요청: 예.** 앱 콘텐츠 페이지에서 **"광고 포함"** 도 별도 신고.
→ **허위 기재는 업데이트 차단·앱 삭제 사유다.**

## 6. Apple ATT — iOS 는 비개인화 광고로 간다

ATT 는 **다른 회사가 소유한 앱·웹을 가로질러 추적**하거나 **IDFA 에 접근**할 때 필요하다.
가이드라인 5.1.2: "App Tracking Transparency API 로 명시적 허락을 받아야 한다."

**핵심 답: 비개인화 광고만 쓰면 프롬프트가 필요 없다.** 비개인화·문맥 광고는 추적이 아니다.
허락이 없으면 IDFA 는 어차피 전부 0 을 반환한다.

⚠ 5.1.2 는 **추적 동의를 조건으로 기능이나 보상을 주는 것을 금지**한다.
→ **"광고 추적에 동의하면 보상" 같은 설계는 불가능하다.**

**권고:** iOS 는 어차피 나중이므로 **비개인화 광고 전용 + ATT 프롬프트 없음**으로 간다.
eCPM 손실은 실질적이지만(미국 보상형이 돈이 되는 곳) 프롬프트·옵트인율 문제와
개인정보 라벨의 "추적에 사용되는 데이터" 항목을 통째로 피한다. 게임이 검증된 뒤 재검토.

⚠ iOS 26 에서 ATT 규칙이 바뀌었는지는 **확인하지 못했다(NOT VERIFIED)**. 불변이라는 것은 추론이다.

## 7. EEA/영국 — 인증 CMP 는 사실상 필수

**2024-01-16 부터** EEA·영국 사용자에게 개인화 광고를 게재하려면
**Google 인증 CMP + IAB TCF 통합**이 필요하다. ([AdMob 13554116](https://support.google.com/admob/answer/13554116))

**미준수 시 결과 — 광고가 끊기지는 않는다.** 비인증 CMP 트래픽은 **비개인화 또는 제한적 광고만** 가능하다.
즉 벌칙은 **셧다운이 아니라 매출 손실**(가장 비싼 인벤토리를 잃는다)이다.

Google 의 EU 사용자 동의 정책은 **EEA + 영국 + 스위스**에 적용된다(스위스 포함 주의).
동의 기록 보관과 철회 안내 제공이 의무다.

**무료 선택지 — Google UMP SDK** ([문서](https://developers.google.com/admob/android/privacy))
- AdMob → 개인정보 보호 및 메시지에서 설정. **TCF 인증됨.**
- ⚠ **필수 구현 패턴:** 매 실행마다 `requestConsentInfoUpdate()` 호출 →
  **광고를 로드하기 전에 `canRequestAds()` 가 true 인지 확인.**
  공식 문서의 함정: "`requestConsentInfoUpdate()` 를 호출하기 전까지 `canRequestAds()` 는 항상 false 다."
  이걸 틀리면 **광고가 하나도 안 나간다.**
- 디버그 설정으로 지역(EEA/UK/CH)을 강제할 수 있다 — EEA 에서 테스트할 수 없으므로 반드시 쓸 것.

⚠ **TCF 버전:** v2.2 가 아니라 **v2.3 이 2026-03-01 부터 필수**다(이미 지남).
미준수 시 제한적 광고로 기본 처리된다. Google CMP 를 쓰면 자동 처리된다.

**결론:** 1차 소프트런치에서 EEA/UK/CH 를 빼면 전부 미룰 수 있다.
**유럽에 손대기 전에 UMP 를 반드시 통합**하고, Capacitor AdMob 플러그인이 UMP 동의 흐름을 노출하는지 먼저 확인할 것.
